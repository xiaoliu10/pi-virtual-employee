## 0.2.127

### 修复：账号登录模型全面可选 + 对话模型选择去禁用（现场反馈三项）

1. **账号登录供应商的模型终于可选**：`availableModels` 此前只读配置里的 `suppliers[].models` 数组，而账号登录（authProvider）供应商的模型在 pi-ai 注册表里、配置数组为空——设置页切换条与对话下拉都看不到它们；`setConversationModel` 校验、`resolveForConversation` 固定校验、`resolveDefaultModel`、config 归一化的默认值自愈四处同款缺口连锁，导致「选了也不生效/根本不出现/默认值被静默重置」。现在：availableModels 合并注册表模型；四处校验统一走 `supplierHasModel`（config 数组 ∨ 注册表）；config 归一化对 authProvider 供应商的非空默认值放行（引擎在解析时对注册表校验）。
2. **IM 对话可在客户端切换模型**：对话顶部下拉不再因 IM 只读而禁用（消息输入框保持只读不变——只放开模型选择，不放开消息注入）。
3. **新建对话可预选模型**：未发送首条消息时（尚无对话可固定），下拉选择直接更新**全局默认模型**——新对话与之后的会话都用它。

### 复审加固

- `resolveDefaultModel` 的失效文案按供应商类型分支：账号登录默认值失效（模型上游改名/登录缺失）时给出对齐登录引导的提示，不再是泛化的「No enabled model configured」。
- 新会话选默认模型走**轻量 IPC**（`model:setDefault`）：不触发 invalidate——在途 IM 流式回复与运行中任务不会被拦腰打断；未固定且空闲的缓存会话被原地热更新，其余在自然重建时生效。
- `effectiveImageCapability` 同步改走 `supplierHasModel`（第六处同类校验漏网——设置页对账号供应商的图片能力显示不再与运行时不一致）。
- 披露：账号供应商列出的模型是**注册表全量**（与登录态无关，登录校验发生在发送时）；`openai-chatgpt` 仅是 OAuth 流程、无对应模型注册表，其供应商不会出现在可选列表。IM 会话被切换模型后，IM 侧用户暂无系统提示（后续可加）。
