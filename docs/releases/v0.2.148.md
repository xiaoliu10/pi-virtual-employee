## 变更一：完整 scoped memory——记忆按 profile/person/conversation 三层隔离（PR #82）

旧记忆层把所有 `tags=memory` 条目取最近 30 条**全局**注入 system prompt：不分人、不分群、同标题纠错是追加（旧事实残留）、摘要截正文前 100 字（纠正后摘要仍是旧事实）、普通工具可铸造 `memory` 标签绕过管理员门禁、consolidation 跨人合并、标题碰撞跨人写入。本版一次做全（调研：`docs/design/memory-system-comparison.md`，设计：`docs/design/scoped-memory.md`）：

- **三层作用域**：profile（全局共享）/ person（平台身份，跨其单聊与群）/ conversation（群记忆）。owner 服务端推导（`person:<channel>:<senderId>` / `conversation:<cid>`），模型给不了，消息/网页/文件注入写不进也读不到别人的记忆。
- **纠错覆盖替代追加**：同 (scope,owner,title) 原地覆盖 + 重建检索 chunks，旧事实从正文与检索同时消失；不同人同标题是独立条目。
- **注入分两点**：profile 走 system prompt（保 KV 缓存）；person/conversation 每轮消息前缀注入（群聊多发送者），前缀只发给模型、不落持久化历史；独立 summary 替代正文前 100 字。
- **检索隔离**：`search_knowledge_base` 过滤他人 person/conversation 记忆；未知 scope fail-closed。
- **整理分区**：consolidation 按 (memory,scope,owner) 分桶后逐桶调 LLM，跨桶 id 拒绝；`memory` 标签保留化（普通知识工具不能铸造/剥离）；记忆不被后台 LLM 自动归档。
- **无人值守身份贯通**：定时任务/自主任务记录 `created_channel`，执行时回挂创建者身份与来源会话，实时与任务写入的记忆同 owner。
- **迁移安全**：三列可空增量，旧行 NULL=profile 保持原可见性；老记忆回填 summary；管理界面加「个人记忆/群记忆」徽标。
- **授权矩阵**：person 默认本人；conversation 需 operator+ 且群内；profile 需管理员（本地控制台=profile）；无验证身份 fail-closed（绝不静默升全局），降级时如实告知。

## 变更二：退化回复门禁与 length 空转熔断——乱码不再直推进群（PR #83）

现场实锤（2026-10-16）：85 分钟长任务轮（46 工具步、压缩过 168 turns/~156k tokens）后半段，qwen 连续 5 次 `stopReason=length`+仅 thinking+零正文空转，盲重试第 7 次拿到 88 字符碎片乱码，因「非空」被当正常回复推群、落库、遥测记 ok。三层修复：

- **length 空转先压缩再重试**：空回合且输出被截断 → 先 `recoverFromContextOverflow` 再 continue（上下文顶格时原样重试必然复现）。
- **连续 3 次 length 空转熔断**（`LENGTH_EMPTY_GIVE_UP`）：不再撞满 10 次重试阶梯捞碎片，提前落入 空→总结→诚实兜底 链。
- **退化回复门禁**（`isDegenerateReplyText`）：非空但 ≥30 字符、CJK<10（假名/谚文计入）、无 4 连拉丁词 → 判碎片 → finalSummary 救援一次 → 仍是碎片则诚实兜底文案。**history 落兜底文案而非乱码**，后续会话不再重水化垃圾；telemetry 新增 `degenerate_reply` 状态（根因可见），my_stats 补中文标签。检测器窄口径（实测形状才拦），短回复/正常中文/英文与代码/工具卡片文案全部放行。
