# v0.2.185

**English**

### Runaway-loop & hung-request watchdog (new)
- **Progress watchdog**: no hard step cap. Judgement is *progress* — a tool call's fingerprint (tool + normalized params + result digest) repeating inside a window escalates L1 observation → L2 soft-stop through the existing abort channel. Any new fingerprint resets instantly, so a task that is moving is never touched. Volatile tokens (epoch ms, ISO dates, UUIDs, 40-hex SHAs) are masked in a single order-independent pass, so a loop cannot re-roll itself clean by swapping tokens.
- **Hung-request circuit breaker**: an in-flight request with a first network event stays exempt (slow TTFT is alive); a request with ZERO events past `hungRequestCapMs` (default 10 min) fires the stall watchdog instead of waiting for its own 30-min request timeout. Fixes the field incident where two conversations were blocked ~30 min behind dead requests.
- In-flight credit now lives for the WHOLE stream lifetime (released on completion, early consumer return, or call failure), not until the stream object exists.
- The local `start` event no longer counts as proof of life — pi-ai emits it before any network I/O.
- Durable MCP tool calls now emit telemetry, so MCP retry loops are visible to the watchdog.
- New `general.progressWatchdog` settings: `enabled`, `stallWindowMs`, `windowSize`, `softStopAfterWindows`, `hungRequestCapMs`.

### Other fixes
- **MCP tools under the durable kernel** hot-update without reopening (own `ve-mcp` extension, in-place registry replacement) — a server connecting late is no longer invisible for the process lifetime.
- **pi-durable 1.4.0 → 1.5.0**: TypeBox removed → pi-schema (all 63 `obj()` keep `{open:true}`), `watchEvents()` rewritten on `Conversation.watch()` + `pi.live` state diffs.
- **Windows script execution**: three-state UTF-8/GBK chunk decoding (valid/incomplete/invalid), `run_script` passes arguments via JSON file instead of the command line, cmd metacharacter injection rejected.
- **`browser_type`** now uses real keyboard input (`pressSequentially`) with read-back verification — React controlled components accept it, and `ok` is no longer hard-coded.
- **Browser runtime self-heal**: auto check/install of the matching Chromium after app upgrades.
- **Auto skill distillation**: an ephemeral review turn after each task distills reusable skills (reuse-first, read-before-write).
- **MCP settings** moved to their own menu.
- **IM group heartbeat**: fourth silent-gate now uses `isConversationStreaming()`.

**中文**

### 失控循环与挂死请求看门狗（新增）
- **进展看门狗**：不做硬性轮次上限。判据是「有无进展」——工具调用指纹（工具名 + 规范化参数 + 结果摘要）在窗口内只有重复时逐级升级：L1 观测 → L2 软停（复用现有 abort 通道）。任何新指纹立即全部重置，正在移动的任务绝不被误伤。易变 token（毫秒时间戳、ISO 日期、UUID、40 位 sha）用单次顺序无关替换屏蔽，循环无法靠换 token 顺序把自己洗成「新工作」。
- **挂死请求熔断**：有首个网络事件的请求仍然无条件豁免（慢首字节是活着的）；但**零事件**的请求超过 `hungRequestCapMs`（默认 10 分钟）即触发看门狗，不再等自己 30 分钟的请求超时。修复线上两个会话各被一个死请求堵住约 30 分钟的事故。
- 在飞记账现在覆盖**整个流生命周期**（完成 / 消费者提前 return / 调用失败才释放），不再在流对象刚创建时就归还。
- 本地 `start` 事件不再算「活着的证据」——pi-ai 在任何网络 IO 之前就发出它。
- durable 内核下 MCP 工具调用现在也产出遥测，MCP 重试循环对看门狗可见。
- 新增 `general.progressWatchdog` 配置项：`enabled`、`stallWindowMs`、`windowSize`、`softStopAfterWindows`、`hungRequestCapMs`。

### 其他修复
- **durable 内核下 MCP 工具热更**：独立的 `ve-mcp` extension，注册表原位替换，无需 reopen——连接较晚的服务器不再对整个进程生命周期不可见。
- **pi-durable 1.4.0 → 1.5.0**：TypeBox 移除改 pi-schema（63 处 `obj()` 全部保留 `{open:true}`），`watchEvents()` 改为基于 `Conversation.watch()` + `pi.live` 状态 diff 重写。
- **Windows 脚本执行**：三态 UTF-8/GBK 分块解码（valid/incomplete/invalid）、`run_script` 参数走 JSON 文件而非命令行、拒绝 cmd 元字符注入。
- **`browser_type`** 改用真实键盘输入（`pressSequentially`）并回读校验——React 受控组件可接受，`ok` 不再写死。
- **浏览器内核自愈**：应用升级后自动检查并安装匹配的 Chromium。
- **自动技能蒸馏**：任务收尾后以临时复盘回合蒸馏可复用技能（复用优先、写前先读）。
- **MCP 设置**独立成单独菜单。
- **IM 群聊心跳**：第四处静默门改用 `isConversationStreaming()`。
