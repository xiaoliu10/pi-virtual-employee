# v0.2.167 — durable 内核默认开启

## 变更

`general.engineKernel` 默认值由 `legacy` 翻转为 **`durable`**：崩溃、强杀、升级中断后，正在执行的任务在新版本/重启后自动接续，答案投递回原会话；恢复后的每一步按**当前**权限重新鉴权（恢复前被撤权的人恢复后不再拥有原权限）。投递经账本防重（发送中崩溃的场景标记 uncertain，不重发、不伪报成功）。

**存量安装同样生效（carry-forward）**：≤0.2.166 的版本会把当时的默认值 `legacy` 物化写进 config，仅改默认值对存量舰队永远无效（stored 值压过新默认）。本版做一次性迁移：持久化里的 `legacy` 且无标记 → 升到 `durable` 并落标记；此后显式设置 `legacy`（配置更新接口或保留迁移标记的 config）会被永久尊重。**显式选过 `legacy` 的存量用户会被本次迁移翻到 durable**——若确需保留，升级后再设一次 `legacy` 即可。

`pi-session` 和已经启用的 `durable` 保持原选择。迁移后的主动回退请通过配置更新接口写入 `legacy`；直接编辑配置时须保留 `engineKernelCarried: true`。

## 配套修复：存储打不开时不再失联

默认翻转的前置条件。此前 `kernel:"durable"` 而 durable 存储无法打开时（磁盘权限、另一实例占用等），每条消息都会抛错——灰度期显式开启者可接受，默认开启不可接受。现在 durable host 打开失败会自动降级 legacy 管线（loud log：`[engine] kernel degraded to legacy`），消息照常应答，只是没有崩溃恢复能力。

## 回归测试

`test-kernel-fallback`（7 用例，含存量迁移、迁移落盘和主动回退保持）：默认值断言；fail-loud 语义保持（未降级的 durable 引擎仍拒绝静默走 legacy 投递）；降级后 legacy 可正常应答且幂等；对 legacy 引擎降级是 no-op。

## 边界（如实声明）

- durable 路径的验收（双会话强杀/撤权/升级中断）在 macOS 完成，Windows 真机仍未验证；启动初始化失败时回退旧管线；这不代表 Windows 全路径已经验收。
- 初始化失败时控制台弹出一次降级提示；日志记录 `[engine] kernel degraded to legacy`。配置项表示所选内核，实际本次启动可能已降级，排除故障后重启会重试 durable。
- 残余风险（显式裁剪）：仅覆盖启动时打开失败；**运行中**存储故障（磁盘满/损坏/锁）会让当轮 send 报错、且引擎继续走 durable 不降级。连续失败的自动降级计数器列为下版候选。
- 想回到旧行为：设置 `general.engineKernel = "legacy"`（存量用户升级后被 carry-forward 翻到 durable 的，升级后再设一次即可永久生效）。
