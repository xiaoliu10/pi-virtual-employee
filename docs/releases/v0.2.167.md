# v0.2.167 — durable 内核默认开启

## 变更

`general.engineKernel` 默认值由 `legacy` 翻转为 **`durable`**：崩溃、强杀、升级中断后，正在执行的任务在新版本/重启后自动接续，答案投递回原会话；恢复后的每一步按**当前**权限重新鉴权（恢复前被撤权的人恢复后不再拥有原权限）。投递经账本防重（发送中崩溃的场景标记 uncertain，不重发、不伪报成功）。

**显式设置过该键的用户不受影响**（设了 `legacy` 的继续走旧管线）。

## 配套修复：存储打不开时不再失联

默认翻转的前置条件。此前 `kernel:"durable"` 而 durable 存储无法打开时（磁盘权限、另一实例占用等），每条消息都会抛错——灰度期显式开启者可接受，默认开启不可接受。现在 durable host 打开失败会自动降级 legacy 管线（loud log：`[engine] kernel degraded to legacy`），消息照常应答，只是没有崩溃恢复能力。

## 回归测试

`test-kernel-fallback`（4 用例）：默认值断言；fail-loud 语义保持（未降级的 durable 引擎仍拒绝静默走 legacy 投递）；降级后 legacy 可正常应答且幂等；对 legacy 引擎降级是 no-op。

## 边界（如实声明）

- durable 路径的验收（双会话强杀/撤权/升级中断）在 macOS 完成，Windows 真机仍未验证；降级路径保证 Windows 上最坏情况是「没有恢复能力的旧行为」，不会失联。
- 想回到旧行为：设置 `general.engineKernel = "legacy"`。
