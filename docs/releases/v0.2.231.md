# v0.2.231

## English

- **Work windows deliver the full report body (#215).** Autonomous work windows now collect every accepted turn's reply and push the complete concatenated text on done and scheduled settlements; the former 500-character `tailExcerpt` truncation is removed (long texts are split for delivery by the IM layer, which already supports segmentation).
- **Work-window pushes are acknowledged and ledgered (#215).** Each window push carries a stable `work:<itemId>:window:<uuid>` occurrence (`kind: work-result`) through the IM delivery ledger. Only an acknowledged `{ ok: true }` marks success; failed or unacknowledged pushes are logged (`delivery not acknowledged`) and surfaced through the error path instead of being silently swallowed.
- **The engine no longer discards deliverables emitted before a bookkeeping call (#215).** The 2026-11-13 field incident: the model emitted a full 2,272-character inspection report alongside `manage_work(set_progress)`, then closed the turn with a 187-character sign-off claiming "report pushed to group" — only the last assistant text was delivered, so the report itself was lost. `send()` now records every assistant message with its tool-call names; a step whose ONLY calls are internal note tools (`manage_work`, `manage_work_items`, `save_to_knowledge`, `save_to_skill`, `remember`) preserves a substantive draft (≥200 chars), and when the final no-tool closing text is shorter and does not contain it, the draft is prepended — closing markers (`[[NEXT_CHECK]]` etc.) stay at the tail. Any non-bookkeeping tool call resets the pending draft, so narration before `run_command`/browser calls stays suppressed; artifact-publishing tools (`save_report`/`save_document`) are deliberately excluded.
- **The delivery channel is stated where the model decides (#215).** The work-window prompt now says explicitly that only the final no-tool text is pushed to the source conversation and that intermediate blocks are private notes; `manage_work` and `save_to_knowledge` descriptions and return receipts repeat that notes and knowledge writes never deliver anything. Resident tasks additionally keep the rule that unconfirmed delivery must never be described as "报告已推群".

Validation: all 146 test suites pass on the integrated code (including the new `assistant-draft-rescue` regression suite; a mutation disabling the rescue fails it, restored code passes), both TypeScript projects pass, and all 16 immutable regions remain unchanged. Windows x64 and macOS arm64 packages must pass the app.asar integrity gate before publication.

Boundaries: the rescue merges only when a substantial draft precedes a strictly shorter pure-text closing; normal chat turns whose final text is the deliverable are byte-identical to before. Push acknowledgement applies to work windows from this version on; v0.2.230-and-older windows remain un-ledgered until boxes upgrade. The trailing-draft rescue covers the default legacy engine path; under the opt-in durable kernel the final answer entry is read the same way and is not rescued yet. Live delivery acceptance on the deployment box is a separate field check, not implied by the test results.

## 中文

- **自主任务窗口推送完整报告正文（#215）。** 工作窗口现在收集每一轮已接受轮次的回复，在 done 与 scheduled 收尾时拼接完整正文推送；移除原 `tailExcerpt` 500 字硬截断（长文由 IM 层按既有分段能力拆分投递）。
- **工作窗口推送带投递回执与台账（#215）。** 每次窗口推送携带稳定的 `work:<itemId>:window:<uuid>` 投递标识（`kind: work-result`）进入 IM 投递台账。只有收到 `{ ok: true }` 回执才记成功；失败或未确认的推送会落日志（`delivery not acknowledged`）并走错误路径，不再静默吞掉。
- **引擎不再丢弃记账工具调用前输出的交付正文（#215）。** 2026-11-13 现场实例：模型在 `manage_work(set_progress)` 同一步输出了 2,272 字完整巡检报告，随后用 187 字「报告已推群」收尾——此前引擎只取最后一条 assistant 文本，报告主体被静默丢弃。现在 `send()` 记录每条 assistant 消息及其工具调用名；仅调用内部记账工具（`manage_work`、`manage_work_items`、`save_to_knowledge`、`save_to_skill`、`remember`）的步骤保留 ≥200 字实质草稿，当最终不调用工具的收尾文本更短且未包含草稿时，将草稿前置合并——收尾标记（`[[NEXT_CHECK]]` 等）保持在末尾。任何非记账工具调用会重置待救援草稿，`run_command`/浏览器调用前的旁白保持抑制；会产生产物推送的 `save_report`/`save_document` 刻意排除在外。
- **在模型决策处写明交付通道（#215）。** 工作窗口提示词明确「只有最后一条不调用工具的文本会推送到来源会话」，中间文本块只是内部笔记；`manage_work` 与 `save_to_knowledge` 的工具描述和返回回执重复说明笔记与知识沉淀不会向任何人推送。常驻巡检规则保留「未经投递确认绝不要写『报告已推群』」。

验证：集成后全部 146 个测试套件通过（含新增 `assistant-draft-rescue` 回归套件；禁用救援逻辑的变异版本会使其失败，还原后通过），两个 TypeScript 项目通过，16 个不可变区域未变。Windows x64 和 macOS arm64 安装包发布前必须通过 app.asar 完整性检查。

边界：救援仅在「实质草稿先于严格更短的纯文本收尾」时合并；最终文本本身就是交付物的普通聊天轮次与之前逐字节一致。推送回执自本版本起对工作窗口生效，v0.2.230 及更早版本的窗口推送在盒子升级前仍无台账。草稿救援覆盖默认 legacy 引擎路径；可显式开启的 durable 内核以同样方式只读最终 answer 条目，暂未做同等救援。部署盒子上的真实投递验收属于独立现场检查，不能由测试结果推定。
