# v0.2.198

## English

Four field incidents on 2026-11-06 (box Nova) traced to the same root pattern: the employee knew *what* to do but not *when to hand control back* — to a human, to the resource owner, or to its own lifecycle. This release fixes the judgement, the resource cascade, and the silence that hid both.

### Ask a human the moment a human is needed

An SMS verification code was sent mid-script; the employee kept polling the background process instead of asking for it, and the code expired before the question ever reached the user.

- New immutable execution-discipline rule: when the next step **must** be done by a person (verification code, password, scan, human confirmation or choice, offline action, third-party approval), ask immediately in one or two lines and **end the turn to wait for the reply** — do not defer by re-polling, waiting for the script to exit, or doing unrelated cleanup first.
- The trigger is the task's real state, **not a fixed scenario list** — the same rule covers any "the next step needs a human" moment.
- Explicitly separated from "ask only for authorization": that rule governs *whether to act*; this one governs *input required to continue* — and the latter may not be delayed.
- Companion rule: while waiting on a background script, read **incremental output** (`manage_process log` with `nextOffset`), not just the running status — the script's own progress lines are the signal that a human is now needed.

### A cancelled task no longer leaves orphans holding shared resources

Cancelling a task left its 15–20 minute query script and Playwright browser running; they held `spay_profile` and every later login bounced off `PROFILE_MASTER_BUSY`.

- `abortSession` now cascades a **process-tree kill** of that conversation's running background processes, before the durable early-return so **every** abort path is covered (admin cancel, progress-watchdog soft-stop, turn watchdog, `/stop`).
- Only the aborted conversation's own processes are touched; other conversations' work is never collateral.
- Logged: `[engine] cascade stop: N background process(es) killed for <conv>`.

### A waiting background process is not a dead loop

A healthy "wait for the login script" loop polls `manage_process`, gets the same "still running" result every time, and the repeat fingerprint read as a runaway — so the progress watchdog soft-stopped the turn.

- `ProgressWatchdog.touch` takes `hasRunningBackground`: when a soft-stop is due and the conversation still has a running background process, the stop is **deferred one window** instead of aborting a legal wait.
- Deferrals are capped (`maxDeferrals`, default 3 ≈ 15 minutes) so a zombie process cannot exempt a turn forever, and any new fingerprint resets the budget instantly.

### Shared stateful resources must be used concurrently

A task held the profile's master directory for its entire run, blocking every other task that needed it.

- New capability rule: browsers' profile directories, login state, account sessions and exclusive file locks are **shared stateful resources** — prefer concurrent-safe usage (clone/copy profiles, hold briefly, release immediately), never occupying the shared master for a whole task.
- When exclusivity is genuinely required, keep it short, explicit, and tell the user which task holds it and roughly how long.
- Generalized to the resource class, not to one site or script; not injected when the browser capability is off.

### Observability: the progress pump finally explains itself

The chat progress pump (introduced in 0.2.192) had never fired on the box, and **no log line existed anywhere in the chain** — "never saw the conversation" was indistinguishable from "saw it but gated".

- Every tick logs the busy set and per-conversation decisions; empty ticks log `busy=0` (proof the pump is alive); arm and FIRE each log a line; `pumpOne` brackets brief generation with start/done lines.

### Quality

- Independent code review on all five changes (no P1/P2 outstanding; every P3 addressed or answered).
- 21 mutation rounds killed across the five changes — including a position mutation (moving a rule from the immutable block back into the replaceable block) and a conversation-filter removal that would have killed *every* conversation's processes.
- Full suite green; typecheck clean; immutable core change acknowledged with reason (execution-discipline rule added deliberately).

## 中文

2026-11-06 在 144 盒子（Nova）上发生的一串现场事故，指向同一个根因模式：员工知道**该做什么**，却不知道**什么时候该把控制权交回去**——交给人、交给资源持有者、或交还给自己的生命周期。本版修复这个判断、资源级联，以及把两者都掩盖掉的静默。

### 需要人参与的那一刻就立刻问人

短信验证码在脚本执行中途发出，员工却继续轮询后台进程、不来要验证码，等它终于开口时验证码已经过期。

- 新增不可变执行纪律：当下一步**必须**由人完成（验证码、密码、扫码、人工确认或选择、线下操作、第三方审批等），立刻用一两句话提问并**结束当前回合等待答复**——不要用反复轮询、等脚本退出、或先做无关收尾来拖延。
- 触发依据是任务的真实状态，**不是固定场景清单**——同一条规则覆盖任何「下一步需要人」的时刻。
- 与「请示只留给三种情况」明确区分：那条管的是*要不要做*（授权），这条管的是*继续做必须拿到的输入*——后者不允许拖延。
- 配套规则：等待后台脚本时必须读**增量输出**（`manage_process log` 传 `nextOffset`），而不是只看运行状态——脚本自己打印的进度就是「现在需要人参与」的信号。

### 取消任务不再留下孤儿进程占着共享资源

取消任务后，它那个 15–20 分钟的查询脚本和 Playwright 浏览器仍在运行，占着 `spay_profile`，之后每次登录都被 `PROFILE_MASTER_BUSY` 挡回。

- `abortSession` 现在会**树杀**该会话正在运行的后台进程，位置在 durable 早退之前，因此**所有**中止路径都被覆盖（管理员取消、进度看门狗 soft-stop、回合看门狗、`/stop`）。
- 只动被中止会话自己的进程，其它会话正在做的工作绝不会被误杀。
- 日志：`[engine] cascade stop: N background process(es) killed for <conv>`。

### 等待中的后台进程不是死循环

一个健康的「等登录脚本跑完」循环会反复 poll `manage_process`，每次都拿到同样的「仍在运行」，重复指纹被当成失控——进度看门狗于是把回合 soft-stop 掉了。

- `ProgressWatchdog.touch` 新增 `hasRunningBackground`：该 soft-stop 时若该会话仍有后台进程在运行，就把这次停止**推迟一个窗口**，而不是掐断一个合法的等待。
- 推迟次数有上限（`maxDeferrals`，默认 3 次 ≈ 15 分钟），僵尸进程不能永久豁免；任何新指纹都会立即重置额度。

### 共享有状态资源必须以可并发的方式使用

某个任务在整个执行期间独占 profile 的 master 目录，挡住了所有其它需要它的任务。

- 新增能力规则：浏览器的 profile 目录、登录态、账号会话、独占文件锁都是**共享有状态资源**——优先用可并发的用法（克隆/复制 profile、按需短时持有、用完立即释放），绝不要为了跑完一个任务长期占着共享 master。
- 确实必须独占时，要短、要明确，并告知用户当前是哪个任务在独占、大约多久释放。
- 泛化到资源类别，而非某个站点或脚本；未开启浏览器能力时不注入这条规则。

### 可观测性：进度泵终于会解释自己

聊天进度泵（0.2.192 引入）在盒子上从未触发过，而**整条链路上没有任何一行日志**——「根本没看到这个会话」和「看到了但被门拦住」完全无法区分。

- 每个 tick 记录 busy 集合与各会话的判定；空 tick 记 `busy=0`（证明泵还活着）；arm 与 FIRE 各记一行；`pumpOne` 在摘要生成前后各记一行。

### 质量

- 五处改动全部经过独立代码审查（无遗留 P1/P2；每条 P3 均已修复或回应）。
- 累计 21 轮变异全部被杀——其中包括一个位置变异（把规则从不可变块挪回可替换块）和一次会话过滤删除（那会杀掉**所有**会话的进程）。
