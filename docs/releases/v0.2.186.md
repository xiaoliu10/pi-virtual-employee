# v0.2.186

**English**

### Scheduled-task progress notes no longer go silent after the scheduler timeout
- A run that outlives the scheduler's 60-min bookkeeping timer used to lose ALL progress notes for its entire overhang (the timer flipped `suppress`), then delivered its result "ok" — the user saw an hour of silence followed by a completion. Overdue runs now keep narrating, with an explicit marker: 「已超过调度器时限，任务仍在执行中；完成后会另发最终结果」.

### Release integrity: byte-level publish verification
- Gitee's CDN served a truncated/stale asset body for ~20 minutes after publish (2026-11-03), while HEAD checks kept returning 302 — auto-update on the box failed sha512 for every profile. Publishing now downloads every artifact back and compares sha512; a mismatch re-uploads once and re-verifies, then FAILS the release. Bad assets can no longer ship as "verified".

**中文**

### 定时任务超时后进度汇报不再全程静默
- 任务超过调度器 60 分钟记账计时器后，旧逻辑把 `suppress` 置位，超时后的整个收尾期一条汇报都不发——但任务实际还在跑、最终成功交付。用户看到的是一小时静默 + 突然一个完成通知。现在超时的 run 继续汇报，并附明确标注：「⚠️ 已超过调度器时限，任务仍在执行中；完成后会另发最终结果」。

### 发布完整性：字节级发布校验
- 2026-11-03 现场：发布后约 20 分钟内 Gitee CDN 对资产返回截断/陈旧内容（94.7MB vs 99.3MB），而 HEAD 检查仍是 302——盒子三个 profile 的自动更新全部 sha512 失败。现在发布脚本对每个产物完整回读下载并比对 sha512；不匹配则删除重传一次再验，仍失败则发布失败退出。坏资产无法再以「已验证」状态发布。
