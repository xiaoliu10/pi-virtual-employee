# v0.2.187

**English**

### Task planning ahead of execution (new)
- Task-shaped messages now get a short numbered plan pushed to the chat BEFORE execution starts, then the same plan is fed to the turn as context so the agent honors what was promised. Simple questions and single-step commands are never planned (no latency tax). A NO_PLAN verdict or a planning failure skips silently — execution is never blocked. The side pass is bounded at 60s and counted as in-flight life.
- Classification is structural, not length-based (a 30-char floor dropped real instructions like 「部署一下测试环境，跑通之后把日志发我」): task verb + multi-step evidence.

### Scheduled-task progress notes no longer go silent after the scheduler timeout
- A run that outlives the scheduler's 60-min bookkeeping timer used to lose ALL progress notes for its entire overhang, then delivered its result "ok" — the user saw an hour of silence followed by a completion. Overdue runs now keep narrating, marked 「已超过调度器时限，任务仍在执行中」.

### Release integrity: byte-level publish verification
- Gitee's CDN served a truncated/stale asset body for ~20 minutes after publish (2026-11-03), while HEAD checks kept returning 302 — auto-update on the box failed sha512 for every profile. Publishing now downloads every artifact back and compares sha512; a mismatch re-uploads once and re-verifies, then FAILS the release. Bad assets can no longer ship as "verified".

**中文**

### 任务规划先行（新增）
- 任务型消息在执行前先出一份简短编号规划，推送到聊天里，再把同一份规划作为上下文交给本轮执行——用户先看到「要做什么」，执行严格按规划来。简单问答和单步命令不规划（不加延迟）；模型判定 NO_PLAN 或规划失败都静默跳过，绝不阻塞执行。旁路调用 60 秒上限，并计入在飞生命周期。
- 任务识别按结构而非长度（30 字门槛会漏掉「部署一下测试环境，跑通之后把日志发我」这类真实指令）：任务动词 + 多步证据。

### 定时任务超时后进度汇报不再全程静默
- 任务超过调度器 60 分钟记账计时器后，旧逻辑把整个收尾期的汇报全部吞掉——但任务实际还在跑、最终成功交付。用户看到的是一小时静默 + 突然一个完成通知。现在超时的 run 继续汇报，并附「⚠️ 已超过调度器时限，任务仍在执行中」。

### 发布完整性：字节级发布校验
- 2026-11-03 现场：发布后约 20 分钟内 Gitee CDN 对资产返回截断/陈旧内容（94.7MB vs 99.3MB），而 HEAD 检查仍是 302——盒子三个 profile 的自动更新全部 sha512 失败。现在发布脚本对每个产物完整回读下载并比对 sha512；不匹配则删除重传一次再验，仍失败则发布失败退出。
