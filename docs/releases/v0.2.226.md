# v0.2.226

## English

### Four fixes: honest progress cadence, readable task titles, legacy settle-gate, and the real system prompt

This release folds in four independently reviewed fixes, each addressing a behavior that was observed in the field on the box.

**Progress notes fire at the configured interval, not on a synthetic early beat (#204).** v0.2.217 introduced a `FIRST_BEAT_MS = 2min` timer so short tasks would narrate at least once. Field feedback the next day: at T+2 a task has **no evidenced progress**, so that early beat could only push a「暂未确认」shell — and the notes read as too frequent (「消息有点频繁了」). The first progress note now waits the full configured interval; an immediate beat was useless, so the early beat is removed.

**Worker task notices use readable titles instead of raw instruction slices (#203).** A pasted solution text with a fenced code block became a worker-task instruction, and every user-facing notice title was a raw `instruction.slice(0, 60)` — leaking prompt text and code fences into the group. `workerTaskTitle()` now derives a one-line task name: it strips fenced blocks and markdown markers, cuts at a natural clause boundary (never mid-clause), and falls back safely when the instruction starts with a code fence.

**The legacy kernel gets the settle-gate it was missing (#202).** After the single-kernel decision, legacy (bare agent-core) became the default — but the settle-gate that verifies a turn actually delivered lived only in the other two kernels. `LegacySettleGate` closes that gap: on eligible turns it runs a verification pass that requires **evidence** (a PASS with no tool calls is sent back for rework), caps consecutive failures at `streak ≥ 2` with an explicit `⚠️` report instead of a fabricated success, and stays fail-open — a verification-turn error (stream break / gateway error) returns the original reply, never swallows it. The gate keeps the tool set (a verification turn must be able to read and re-check) and is streak-isolated per session, cleared on pass/release.

**The provider sees the agent's real system prompt on the pi-session path (#201).** A worker reading SLS logs produced three fenced bash/cmd/powershell blocks as chat text and called **zero tools**, while quoting its own system prompt — the provider was receiving the loader stub「VE session host」instead of the real employee prompt, so the model had no tool-use discipline. The pi-session projection now carries the real prompt (the stub remains only a fallback when the agent has none). The CJK token estimator also folds the projection `sections` through the CJK-aware rate instead of pi's chars÷4 under-count, so the budget gates see the real prompt's true size.

Verification: the four branches merge into main with **zero conflicts**; the merged tree passes **142 test suites** (legacy-settle-gate 10, worker-task-title 9 new), both typecheck projects are clean, and the immutable-kernel gate reports 16 guarded regions unchanged. All four PRs had no actionable Copilot review comments (quota placeholder only).

## 中文

### 四项修复：进度节奏诚实、任务标题可读、legacy 收尾验证、真实系统提示

本版合入四个独立评审过的修复，各自对应盒子上观测到的真实现场行为。

**进度汇报按配置间隔触发，不再有合成的提前首拍（#204）。** v0.2.217 引入 `FIRST_BEAT_MS = 2min` 计时器，让短任务至少播报一次。次日现场反馈：T+2 时任务**还没有可证的进展**，提前首拍只能推一个「暂未确认」的空壳——而且汇报显得过于频繁（「消息有点频繁了」）。现在第一条进度汇报会等满配置间隔；立即首拍没有用处，因此直接移除。

**worker 任务通知用可读标题，不再裸截指令前缀（#203）。** 一段带代码块的解决方案文本被当成 worker 任务指令后，每条面向用户的通知标题都是裸 `instruction.slice(0, 60)`——把提示文本和代码围栏泄进了群里。`workerTaskTitle()` 现在派生一行任务名：剥离代码围栏与 markdown 标记、在自然从句边界截断（绝不半句截断），指令以代码围栏开头时也有安全兜底。

**legacy 内核补上了它缺失的收尾验证（#202）。** 单内核裁定之后，legacy（裸 agent-core）成为默认内核——但验证回合是否真正交付的 settle-gate 此前只存在于另外两个内核。`LegacySettleGate` 补上了这个缺口：符合条件的回合会跑一轮验证，**必须有证据**（无工具调用的 PASS 会被打回返工）、连续失败到 `streak ≥ 2` 封顶并交付显式 `⚠️` 报告而非伪造成功、全程 fail-open——验证回合出错（流断/网关错误）退回原始回复，绝不吞掉。验证回合保留工具集（要能真实 read 复核），streak 按会话内存隔离、pass/release 后清除。

**pi-session 路径上 provider 看到的是 agent 的真实系统提示（#201）。** worker 查 SLS 日志时三轮分段回复全是 bash/cmd/powershell 代码块当聊天文本、**一个工具都没调用**，还逐字引述系统提示——provider 收到的是 loader stub「VE session host」而不是真实员工提示，模型因此没有工具调用纪律。pi-session 投影现在携带真实提示（stub 仅在 agent 无提示时兜底）。CJK token 估算也把投影 `sections` 按 CJK 感知费率计入，替代 pi 的 chars÷4 低估，预算闸门因此看到真实提示的真实大小。

验证：四个分支合入 main **零冲突**；合并后的代码树通过 **142 个测试套件**（新增 legacy-settle-gate 10 例、worker-task-title 9 例）、双 typecheck 零错、不可变内核闸门报告 16 个守护区未变。四个 PR 的 Copilot review 均无可处置意见（仅配额占位）。
