# v0.2.214

## English

### The kernel is back on agent-core: compaction now touches what the model actually reads

Field evidence (handoff-worker-context-20261109.md) proved the durable-kernel split brain: `maybeCompact` rewrote the in-memory projection while the real request was rebuilt from the durable transcript — "compacted 377 turns" six times in a row with tokens climbing 209k→298k until every call died on litellm 400. The user ruled: roll the kernel back, stop depending on the component.

- **Default kernel is `legacy` (pi-agent-core) again**, with a one-time reverse migration for existing installs (explicit `durable` choices made before this build are reset once, marker `engineKernelReset202611`; a deliberate re-selection afterwards still sticks). Under legacy, compaction operates on the actual prompt source — the theater class is gone structurally.
- **Compaction invariant (both paths)**: a summary that does not REDUCE the transcript/ledger is dropped, not applied — `skipReason: "no_reduction"`, honest warn with partition id and token counts. The compact→still-over→compact 6-failure loop cannot form. Pinned by tests on the CCL core and the legacy `maybeCompact`.

### Work sessions own their context: the CCL ledger

- **`work:<id>` sessions assemble context from a persistent ledger** (sqlite `context_entries`): request rows (scaffold-stripped), tool digests in call order, final replies, compaction summaries — surviving restarts and session rebuilds. The 40-line rehydrate cap no longer applies to work sessions; IM keeps it until the RouterSession phase.
- **Tool digests are bounded and secret-masked** at the single collection point (the telemetry wrapper): 240-char briefs, key-name AND value-shape masking (Bearer / key=value / PEM blocks) on args, results and error text; tools still receive raw params. Collection is gated to work sessions and can never flip a successful call.
- **Turn commits are one transaction** — a mid-turn failure can no longer leave a half turn (request without reply) replaying into every later window.
- **Recovery brief**: after a crash/restart, recovered tasks get their first window prefixed with the latest ≤8 tool digests plus a verify-before-repeat guard, so the agent checks the live state instead of blindly redoing work.
- **No auto-revival** (supersedes the 2026-10-23 auto-extension ruling; the flood-loop root fix): timed-out or failed tasks settle into an honest pause (`waiting_human`) and only a human re-enters them. Model-declared NEXT_CHECK, the parse-failure soft deferral (3-strike breaker) and bounded silent retries are unchanged.

### A task turn may no longer end with pure narration

Field incident: 「继续 登录生产后台管理」 was answered with "我来尝试登录…先检查一下当前环境可用的工具" and then silence — zero tool calls, turn done, task never ran.

- **Narration guard (both kernels)**: a task-shaped turn that made zero tool calls is not delivered as-is — the model is forced to continue exactly once (durable path: one nudge input, since a bare continue provably settles `nothing_to_answer`; legacy path: safeContinue with the driveTurn replay fallback). Still zero tools → the reply is delivered WITH an honest notice. Strictly one-shot; aborted turns are never nudged; the continuation keeps the turn's RBAC identity and memory context.
- **Short imperative detection** (`looksLikeImperative`): task verb + imperative lead / verb-initial, with anchored and mid-sentence question-word exclusions — the literal 11-char field message is covered, while 「登录密码是什么」「帮我分析下为什么登录失败」 stay Q&A.
- Triage verb vocabulary completed (登录/检查/验证/打开/访问/上传/同步/重启); the anti-imitation sweep now strips the notice SEGMENT from merged reply+notice rows instead of deleting genuine answers.

### Design record

`docs/design/router-worker-core.md`: the single-kernel Router/Worker architecture — RouterSession/WorkSession, the context layer (CCL), context-partition law (conversation streams partition hard by trigger; work objects soft-share by permission), memory contract (person owner key = `person:<channel-family>:<staffId>`, single chat and group chat of the same person share memory), and the P1–P4 phase plan. The durable component itself is retired and will be removed in a follow-up.

## 中文

### 内核回到 agent-core：压缩终于作用在模型真正读到的东西上

现场实锤（handoff-worker-context-20261109.md）证明了 durable 内核的投影/事实源分裂：`maybeCompact` 改的是内存投影，真实请求却从 durable transcript 重建——「compacted 377 turns」连打六次一条没少、token 209k→298k 单调上涨，直到 litellm 400 全废。用户裁定：回退内核，不再依赖该组件。

- **默认内核回到 `legacy`（pi-agent-core）**，存量安装做一次性反向迁移（本版本之前显式选过 durable 的重置一次，marker `engineKernelReset202611`；之后再显式选择仍然粘滞）。legacy 下压缩对象就是真实 prompt 源——压缩表演这一类问题结构性消失。
- **压缩不变量（双路径）**：不能使 transcript/账本变小的摘要一律丢弃不落账——`skipReason: "no_reduction"`，带分区 id 与前后 token 数的诚实告警。「压缩→仍超限→再压缩」的 6 连败循环无法成形。CCL 核心与 legacy `maybeCompact` 均有测试钉死。

### 工作会话拥有自己的上下文：CCL 账本

- **`work:<id>` 会话从持久化账本装配上下文**（sqlite `context_entries`）：请求行（剥脚手架）、按调用序的工具摘要、最终答复、压缩摘要——跨重启、跨会话重建存活。40 行 rehydrate 帽不再作用于工作会话；IM 会话保留至 RouterSession 阶段。
- **工具摘要有界且脱敏**，采集点唯一（telemetry 包装层）：240 字符上限，键名与值形态双重掩码（Bearer / key=value / PEM 私钥块）覆盖参数、结果与错误文本；工具本体仍收原始参数。采集只对工作会话开启，且永远不会翻转成功调用。
- **回合落账是单事务**——中途失败不再留下「有请求无答复」的半截回合在后续每个窗口重放。
- **恢复简报**：崩溃/重启后，被恢复任务的第一个窗口前缀注入最近 ≤8 条工具摘要 + 「先核对现场」护栏，让 agent 先验证现场而不是盲目重做。
- **删除自动顺延复活**（取代 2026-10-23 的自动顺延裁定；flood-loop 根因修复）：超时/失败任务落入诚实暂停（`waiting_human`），只有人能重新进入。模型自声明 NEXT_CHECK、解析失败软顺延（3 连击断路）与有界静默重试保持不变。

### 任务回合不得以纯叙述收尾

现场事故：「继续 登录生产后台管理」得到一句「我来尝试登录…先检查一下当前环境可用的工具」后彻底无声——零工具调用、回合结束、任务从未执行。

- **叙述守卫（双内核）**：任务型回合零工具调用不得原样投递——强制模型恰好继续一次（durable 路径：一次催办 input，因为裸 continue 被实测证明必然 `nothing_to_answer`；legacy 路径：safeContinue + driveTurn 重放回退）。仍零工具 → 投递并附如实说明。严格单次；已中止的回合绝不催办；续跑保留本回合的 RBAC 身份与记忆上下文。
- **短祈使任务句检测**（`looksLikeImperative`）：任务动词 + 祈使引导/动词开头，尾锚定与中置疑问词双重排除——现场 11 字原句被覆盖，而「登录密码是什么」「帮我分析下为什么登录失败」仍是问答。
- triage 动词表补齐（登录/检查/验证/打开/访问/上传/同步/重启）；防模仿清扫改为从「真实答复+通知」合并行中剥离通知段落，不再整行删除真实答复。
