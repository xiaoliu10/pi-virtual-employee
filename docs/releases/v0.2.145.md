# 0.2.145（2026-10-13 发布）

## 变更一：模型会话亲和默认开启（PR #72，用户裁定：省 token，缓存命中更高）

- 背景：pi 桌面壳为模型配置加了「会话亲和」——每个 LLM 请求带会话标识 header，同一会话粘同一上游，网关侧 prompt 缓存实际命中。VE 依赖的 pi-ai 1.1.0 早已实现该能力，但**默认只对 OpenRouter 端点启用**——VE 的 LiteLLM/中转网关永远不命中，所以过去等于没开。
- 实现：模型解析处为所有模型显式置位 `compat.sendSessionAffinityHeaders`，header 格式保留 pi-ai 自动检测（openrouter 域名 → `x-session-id`；openai 协议 → `session_id` / `x-client-request-id` / `x-session-affinity`；Anthropic 协议 → `x-session-affinity`）。会话标识取 conversationId——IM 会话、定时任务、控制台天然各自独立，互不抢占同一后端。
- 关闭方式：`manage_settings` 设 `model.sessionAffinity: false`（严格网关拒收未知 header 时的 kill switch）。
- 审查知情项：真 Anthropic OAuth（账号登录）路径 pi-ai 在 header 构造前提前返回，该标志在此路径上惰性（无风险亦无收益）；`openai-responses` 协议不看此标志（有 sessionId 就发，pi-ai 既有行为）。
- 现场效果待验证：Nova（LiteLLM qwen）同会话请求将带亲和 header，若 LiteLLM 启用对应路由策略则粘同后端、提升隐式缓存命中——发版后观察缓存命中 token 数确认。

## 变更二：心跳旁路任务汇报质量（PR #73，现场驱动）

- 现场问题：Nova 旁路任务（Playwright 访问 spay 提交工单）的心跳汇报是「已完成：暂未确认；剩余：暂未确认；正在：任务执行中，正在核实最新进展；卡点：暂无」——被用户判定「没有任何有效的信息」，而转录里明明写着「登录态有效不用验证码，改用 Playwright 脚本访问 spay」。
- 病灶三处：① 兜底路径只从结构化报告取数，最新助手叙述从不进「正在」；② 占位文案「正在核实最新进展」是自我循环的废话；③ LLM 指令只禁编造，没说明「什么算依据」。
- 修复：`progress.ts` 给「正在」字段建三级证据链（结构化 doing → **最新一条助手可见叙述** → 诚实占位「执行中，尚无已确认的阶段结论」）；`engine.ts` 汇报指令补「执行记录本身就是依据」——助手叙述、工具调用与工具返回里真实发生的事必须如实归纳，工具正在做什么、卡在哪一步、用户还需做什么，都是有效信息；不许因「没有现成进度数字」整段写暂未确认。
- 效果（同一现场）：正在字段从废话变为「登录态有效不用验证码，改用 Playwright 脚本访问 spay」；仍不编造——没有证据的字段照实写暂未确认。
