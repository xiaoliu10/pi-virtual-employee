# v0.2.166 — 崩溃恢复完整落地：真实会话接入 durable + 撤权/升级/投递三重验收

## 中断恢复（核心）

`general.engineKernel: "durable"` 下，真实会话执行完整进入 durable：

- **执行**：`EmployeeEngine.send()` 走 durable 运行时（`src/engine/durable/runtime.ts`）；模型/凭据按当前配置在每次请求时解析，恢复后的请求同样重走 VE 解析层。
- **身份**：持久化的是平台验证的 staffId **引用**，角色每次由当前配置重算——崩溃后撤权立即生效（本版专项验收）。
- **恢复**：重启后扫描 `submissions` 的 queued/placed 找未完成工作（不再依赖调度器认领状态），轮询到真正终态才取答案；恢复结果经账本投递回原会话。

### 三条真实验收（每条都带变异验证）

| 场景 | 结果 |
|---|---|
| **双会话强杀**：两会话同卡在工具中 → SIGKILL → 重开 | 两会话都续跑、各回各会话、答案各投递一次；unsafe 不重跑、已完成工具不重跑 |
| **撤权后恢复**：恢复前撤掉 admin | 被降级者恢复后 `role=viewer`、guarded 工具被拒；对照组（仍 admin）正常放行 |
| **升级中断**：工具执行中触发 `prepareToInstall` 的 close（含 8 秒上限 race） | 新版本启动后该 run 自行接续，投递一次 |

变异验证均证明测试会失败：删 `resume()` / 只恢复一个会话 / 恢复时丢身份 / 身份串号 / close 时顺手 abort / 退回旧游标——全部被抓。

## 验收暴露并修复的真实缺陷

1. **恢复扫描用错数据源**：`inspect()` 在 resume 前返回空，两会话只恢复一个、另一个静默丢失（正是原始事故形态）。改为直接扫 submissions。
2. **假答案投递**：`waitForIdle` 在 run 重新入队前返回，把「执行已暂停」当真答案投出去。改为轮询终态。
3. **投递重复风险**：发送中崩溃（attempting）原会重发。改为 `uncertain`——不重发、不伪报成功，待人工确认；`pending` 仍可安全重试。
4. **UI 同毫秒丢消息**：单时间戳游标永久跳过同毫秒第二条消息（提问+即时回复形态）。改 `(created_at, rowid)` 复合游标，IPC/preload/ChatPage 全链改型。
5. **收尾门禁三处**：工具证据改 `afterTools` 且验证轮内重新取得；run 身份改提交级 `inputs`（跨注入与重启稳定）；hook 能力缺失时告警不再静默。

## 执行纪律（内置，勿删）
