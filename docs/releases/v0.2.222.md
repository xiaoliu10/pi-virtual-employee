# v0.2.222

## English

### Pi SDK family upgraded to 1.5.2 — including the runtime the box actually installs

The pi family version-locks itself (every package pins its exact sibling versions), and VE had drifted into a mixed tree: pi-agent-core/pi-coding-agent at 1.2.0 while pi-ai/chord/pi-durable sat at 1.5.0. This release aligns the whole family at 1.5.2.

Two upgrade sites matter, because they feed different kernels:

- **`resources/pi-runtime-lock/`** — the runtime source the box actually installs. It ships as `extraResources`; on the user's machine `src/runtime/bootstrap.ts` runs `npm ci` into `userData/pi-runtime`, and `src/engine/imports.ts` (the only resolution point) dynamically imports it. pi-coding-agent goes 1.2.0 → 1.5.2, so the **pi-session kernel path** now natively carries both compaction fixes from 0.2.221 (thinking omitted from the summarizer, #9512 output-limit removal) instead of relying on the vendored copies.
- **Root `package.json`** — pi-agent-core (inside the asar; the legacy default kernel drives it), pi-ai, pi-durable, chord, and pi-coding-agent (type-only; excluded from the asar by `files`).

`src/engine/pi-compaction.ts` vendoring remains necessary — pi-agent-core 1.5.2 still exports no compaction primitives, so the 0.2.221 backports keep applying to the legacy default kernel.

### Verification

Both typecheck projects clean (1.5.2 breaks none of the APIs VE consumes, including the `CustomAgentMessages` declaration-merging extension point), all 140 test suites pass, both platform asar gates pass, and a new real-install probe (`scripts/probe-pi-runtime-install.mjs`) runs the production registry chain (npmmirror → gitee-mirror → npmjs) into a temp dir and proves the pinned runtime installs and self-checks at 1.5.2 — measured 3s, with the #9512 fix confirmed present in the installed tree. Installer size 94.85 MiB, still 5.15 MiB under the 100 MiB asset cap.

One observation we are deliberately *not* attributing: the asar file count this build reports (10,783) differs from builds of 0.2.221 (12,135). Our initial guess — an upstream dependency swap — was disproved during review (the swapped package is dev-chain only and never enters the asar; the production chain actually grew). The integrity of this build is proven directly instead: per-package asar counts match each package's 1.5.2 tarball, the 17 runtime invariants pass, and the lockfile grew by two packages. The historical count difference is under separate investigation and has no known effect on what ships.

## 中文

### pi SDK 整族升级到 1.5.2——包括盒子实际安装的那份运行时

pi 家族互相锁死同版本（每个包都精确钉死兄弟包版本），而 VE 此前已漂移成混合树：pi-agent-core/pi-coding-agent 在 1.2.0，pi-ai/chord/pi-durable 却在 1.5.0。本版把整族对齐到 1.5.2。

两处升级点分别喂不同的内核，都需要交代：

- **`resources/pi-runtime-lock/`**——盒子实际安装的运行时来源。它作为 `extraResources` 随包发运；在用户机上由 `src/runtime/bootstrap.ts` 执行 `npm ci` 装到 `userData/pi-runtime`，再经 `src/engine/imports.ts`（唯一解析点）动态 import。pi-coding-agent 1.2.0 → 1.5.2，意味着 **pi-session 内核路径**原生携带 0.2.221 的两个压缩修复（摘要器省略 thinking、#9512 移除输出上限），不再依赖 vendored 副本。
- **根 `package.json`**——pi-agent-core（在 asar 内，legacy 默认内核直驱）、pi-ai、pi-durable、chord，以及 pi-coding-agent（仅 `import type`，已被 `files` 排除出 asar）。

`src/engine/pi-compaction.ts` 的 vendoring 仍然必要——pi-agent-core 1.5.2 依旧不导出压缩原语，0.2.221 的两个 backport 继续作用于 legacy 默认内核。

### 验证

双 typecheck 零错误（1.5.2 未破坏 VE 消费的任何 API，含 `CustomAgentMessages` 声明合并扩展点）、140 个测试套件全过、双平台 asar 闸门通过；新增真装探针（`scripts/probe-pi-runtime-install.mjs`）按生产 registry 链（npmmirror → gitee-mirror → npmjs）真实安装到临时目录，实测 3 秒装好 1.5.2 并通过版本自检，确认 #9512 修复存在于装好的运行时。安装包 94.85 MiB，距 100 MiB 资产上限仍有 5.15 MiB 余量。

一个我们**刻意不做归因**的观察：本版构建的 asar 文件数（10,783）与 0.2.221 的构建（12,135）不同。最初猜测——上游依赖替换——已在 review 中被否证（被替换的包只在 dev 链、从不进 asar；生产链实际是增长的）。本构建的完整性改用直接证据证明：asar 逐包计数与各包 1.5.2 tarball 一致、17 项运行时不变式全过、lockfile 净增两个包。历史计数差异另行排查，对本次发运内容无已知影响。
