# 0.2.142（2026-10-09 发布）

## 变更：真实时间戳改每轮注入（现场驱动：VE 用 9 月旧日期拒绝查 10 月数据）

- 现场闭环：对账 VE 在 10-09 自报「现在是 2026-09-30，10 月份没有数据」拒绝查询。核查：`get_current_time` 工具存在且无条件注册、prompt 规则也教了、定时任务第 0 轮有【系统注入的真实执行时间】戳——但**工作项窗口 prefix 完全没有当前时间行**，且定时任务戳只在第 0 轮（stall-resume 轮跳过、续轮跨天漏打）。长链条 transcript 全是旧日期，模型从历史锚定「今天」；
- 修复：① 工作项窗口 prefix 每轮新增 `【当前时间】YYYY-MM-DD（周X）HH:MM:SS，北京时间——「今天/昨天/本月」等口径以此为准，不要从历史消息里的旧日期推断今天`；② 定时任务时间戳改**每轮**都打（跨天链条/续轮/stall-resume 不再漏打；上下文重建按单条消息剥离，多戳互不污染）；③ prompt 时间口径规则措辞同步「定时/自主任务每轮消息开头都会注入」（prompt-integrity 守护区域已按流程 IMMUTABLE_ACK re-pin——仅措辞，红线语义扩展未削弱）；
- 设计原则：确定性信息（当前时间）不能依赖模型「记得调工具」，要每轮确定性注入；
- 复审 0H/0M/3L：3 条 L 均措辞硬化（标记名统一/「以最新一条为准」消歧/learn 轮无戳备案），并入后续措辞调整批。

## 变更：心跳进展汇报——去英文模板、强制四段结构（现场驱动：汇报照抄「## Goal…## Constraints & Preferences」且只有目标复述）

- 根因：progressContextSlice 已排除压缩总结角色——但**应用重启后**压缩总结从历史重建为普通 assistant 消息，角色过滤失效，英文模板随上下文尾巴进入心跳 LLM 被照抄；
- 修复三层：
  - **模板拦截**：新增 `src/engine/progress.ts` 纯函数标准化层——压缩模板双标题签名拒绝（`## Goal` + `## Constraints` 同时出现；中文 markdown「## 已完成」与普通英文词不误伤）；上下文切片与输出两侧双重过滤（thinking 不参与签名判定）；
  - **四段结构强制**：心跳 LLM 汇报必须输出「已完成：…；剩余：…；正在：…；卡点：…」，逐项独立限长（50 字，**卡点 80 字**——旧全局截断会把整条卡点切掉）；缺项/模板/blob 输出自动落回确定性兜底（同样四段，查不到的如实写「暂未确认」——严禁没依据说「无」或编数字）；
  - **确定性回退升级**：优先引用 transcript 里已有的四项叙述（**当前任务边界**——不跨任务复用旧任务的数字/卡点；单标签只算普通叙述不算证据），标题 request 优先（旧压缩 goal 仅兜底）；
- 复审两轮（1H/2M/3L + 0H/2M/6L）全部处置：H1 兜底正则过宽误伤合规汇报（收紧到双标题签名+英文模板标题前缀）；M1 跨任务复用边界；M2 测试 stub 估算签名裸数字 → NaN 静默穿透（4 处 stub 忠实化 + fixture 用真实 CJK 计数过 2k 门 + 新增门槛测试）；L1 thinking 不参与签名 / L2 卡点独立配额 / L3 占位降级 / L5 签名单一出处均已修；L4/L6 及模板措辞硬化记 follow-up；
- 新增 test-progress.mjs（19 用例）+ test-context/test-engine-retry 扩充（28/15 用例）。
