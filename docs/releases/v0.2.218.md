# v0.2.218

## English

### Zero-tool process narration no longer masquerades as a task result

A worker finished a turn with a process-only line such as "先确认一下当前环境和可用工具：" and **no tool calls at all**, yet that narration was delivered and settled as the task's final result. The earlier input-side guard missed it because the sentence did not match the task-verb list. The detection now keys on the reliable signal — the **output shape**: a zero-tool, narration-shaped turn. The policy is fail-open: only a structurally certain dangling narration (mid-sentence colon / lead-in that can never be a result) is replaced by an honest system notice; sentence-form narration is still delivered verbatim with a notice appended, so an optional narration can never suppress a real answer. Such turns are flagged explicitly (`narration_suppressed` / `narration_noted`) and never settle as a successful result, enter the knowledge-base outcome archive, or count as `ok` in telemetry; autonomous windows pause for a human instead of burning budget re-driving a turn that did nothing. Real answers already delivered inside a merged (answer + notice) history row are preserved — the notice paragraph is stripped on re-import, not the whole row.

### Screenshots now carry their real vision-token cost — image-heavy automation can no longer wedge the compaction

A screen-automation worker (~30 desktop screenshots in one turn) hit the provider's 204,800-token hard limit while the app's estimator measured the same transcript at ~3.8k tokens, so compaction kept "succeeding" without ever shrinking it. The estimator charged each image a flat 1,200 tokens; a real desktop frame costs roughly 5–15k (field-derived mid-range ~6k), an almost 6× under-count. Each image part is now billed at a conservative 6,000 tokens (pi's flat baseline is subtracted first, so a block is never double-counted), across every message role. Overflow recovery additionally strips old screenshots deterministically: it protects the live tail first, and if the transcript still does not fit, narrows protection (last 2 → 1 → 0 messages) until it does, then re-checks against the usable-window budget before claiming recovery — a recovery that still cannot fit falls through to hard truncation and, if even that fails, ends honestly instead of retrying into the same wall.

### The single-instance profile lock uses process identity, not just a PID

Cross-session updater launches could make two instances write one profile's SQLite at once (robot received messages but never replied). Three lock defects are fixed: an `EPERM` from `process.kill` (a live process in another Windows session) was mistaken for "dead" and its lock reclaimed; Windows PID reuse made a recycled pid look alive and block startup; and an unconditional unlink on quit let a dying instance delete its successor's lock. The lock now records `pid|startTime|token` — start time defeats PID reuse, the random token defeats "same pid, new process" — probes are conservative (only a definite "no such process" reclaims; an indeterminate probe never hard-blocks startup), acquisition is atomic with bounded retry against racing starters, a refused launch exits immediately instead of continuing to open the database, and quit removes only the lock this process owns.

### MCP external tools get their own settings menu

MCP server configuration moves out of the general settings tab into a dedicated top-level "MCP 外部工具" menu, with its own icon and page header. Save and test-connection behavior is unchanged — this is a layout reorganization only.

### The browser runtime self-heals: missing or mismatched Chromium is installed automatically

Playwright's Chromium is now checked against the exact revision the bundled Playwright requires; a missing binary or a version mismatch after an app upgrade triggers an automatic install. The installer runs the Playwright CLI inside asar with the app's own Electron binary (`ELECTRON_RUN_AS_NODE`), so the machine needs no standalone Node (the damaged Node shim that caused the original incident is bypassed). The official CDN falls back to the npmmirror mirror on failure; headless mode uses the dedicated headless-shell binary with a dual-binary readiness check; a startup prefetch, first-use wait, and a settings status card (progress / retry / manual reinstall, gated on the browser being enabled) round it out.

### Finished tasks automatically distill reusable skills

After a scheduled or autonomous task finishes, an ephemeral review turn (never entering the transcript, never pushed) turns whatever reusable procedure emerged — including the working script itself — into a skill under the skill directory's `scripts/`, so the next similar run reads the skill and executes the script instead of rewriting it from scratch. It follows the Hermes discipline: prefer updating an in-use skill, then extending a related one, then adding a support file, and only creating a new skill as the last resort, with read-before-write and an explicit non-capture list (environmental failures, negative tool assertions, one-off narration, approaches that never worked).

## 中文

### 零工具的过程叙述不再冒充任务结果

worker 一轮只产出「先确认一下当前环境和可用工具：」这类过程性文字、**完全没有调用工具**，却被当成任务最终结果投递并结算成功。早先的输入侧守卫因为这句话没命中任务动词表而漏判。现在改为以可靠的**输出形态**为信号：零工具 + 叙述性输出的回合。策略是 fail-open——只有结构性确定不可能是结果的悬空旁白（半截冒号、引导语）才替换成如实的系统通知；句形叙述仍然原样投递并附上通知，可有可无的旁白绝不至于吞掉真正的答案。这类回合被显式打标（`narration_suppressed` / `narration_noted`），不会结算为成功结果、不会写入知识库「任务结果」归档、telemetry 也不记 `ok`；自主任务窗口遇到这种回合会暂停等人，而不是空转预算反复驱动一个什么都没做的回合。已经投递给用户的真实答案若与通知合并在同一历史行，重新导入时只剥通知段、保留答案，不再整行丢弃。

### 截图按真实视觉 token 计费——图像密集型自动化不再把压缩卡死

一个屏幕自动化 worker（单轮约 30 张桌面截图）撞上 provider 的 204,800 token 硬上限，而应用估算器把同一份 transcript 算成约 3.8k token，于是压缩反复「成功」却始终缩不下去。原来每个图块只收固定 1,200 token，而真实桌面截图一帧约 5–15k（现场反推中值约 6k），低估近 6 倍。现在每个图块按保守的 6,000 token 计费（先扣掉 pi 的固定基线，绝不重复计数），对所有消息角色统一生效。超限恢复还会确定性地剥除旧截图：先保护活尾，若仍然装不下就逐级收窄保护（最后 2 条 → 1 条 → 0 条消息）直到满足，并在宣告恢复前按可用窗口预算复核——实在放不下就落到硬截断，连截断都不行则诚实结束，而不是重试撞同一堵墙。

### 单实例 profile 锁改用进程身份，而不只是 PID

跨会话的更新器拉起曾让两个实例同时写同一个 profile 的 SQLite（机器人收到消息却不回复）。三个锁缺陷一并修复：`process.kill` 抛出的 `EPERM`（另一个 Windows 会话里的存活进程）曾被误判为「已死」而回收锁；Windows 的 PID 复用让被回收的 pid 看起来仍存活、阻止启动；退出时无条件删锁会让正在退出的旧实例删掉继任者刚写的锁。锁内容现在记录 `pid|startTime|token`——启动时间破 PID 复用、随机 token 破「同 pid 新进程」；探测保守化（只有确定的「无此进程」才回收，不确定态绝不硬挡启动）；加锁原子化并对竞争启动做有限重试；被拒启动时立即退出而不是继续开数据库；退出时只删本进程持有的锁。

### MCP 外部工具独立成设置菜单

MCP 服务器配置从「通用」设置页抽出为独立的一级菜单「MCP 外部工具」，带独立图标与页头标题。保存与测试连接的逻辑完全不变，只是布局重组。

### 浏览器内核自愈：缺失或版本不匹配的 Chromium 自动安装

现在会按随包 Playwright 实际要求的 revision 检查 Chromium；二进制缺失、或应用升级后版本不匹配都会触发自动安装。安装器用应用自身的 Electron 二进制（`ELECTRON_RUN_AS_NODE`）跑 asar 内的 Playwright CLI，机器无需独立 Node（绕过了导致原始事故的损坏 Node shim）。官方 CDN 失败自动回退 npmmirror 镜像；headless 模式使用专用 headless-shell 二进制并做双二进制就绪校验；另含启动预取、首次使用等待，以及设置页状态卡（进度/重试/手动重装，受浏览器启用开关门控）。

### 任务收尾自动蒸馏可复用技能

定时或自主任务结束后，会跑一个 ephemeral 复盘回合（不进转录、不推送），把本次跑通的可复用流程——连同可用的脚本本身——沉淀成技能、放进技能目录的 `scripts/`，下次同类任务直接读技能跑脚本，而不是从头重写。遵循 Hermes 纪律：优先更新在用技能，其次扩展相关技能，再次才新增附属文件，新建技能是最后手段；并坚持先读后写、明确的不捕获清单（环境性失败、工具负面断言、一次性叙述、没走通的方法）。
