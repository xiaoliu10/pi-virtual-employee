## 0.2.103

### 新特性

- **原生 MCP 连接器**（pi 0.99 起 CLI 层原生支持 MCP；虚拟员工构建在 `pi-agent-core` 之上，在引擎空间实现同等能力）：配置存 `capabilities.mcp`（`enabled` + `servers[]`），格式兼容标准 `mcpServers`（Claude Desktop / Cursor / pi 的 mcp.json 可直接拷贝），支持 stdio（command/args/env/cwd）与 Streamable HTTP（url/headers），`env`/`headers` 支持 `${环境变量}` 插值，单服务器可独立停用。工具名 `mcp__<服务器>__<工具>` 防冲突，调用结果按内容块渲染，`isError`/超时降级为诚实的错误文本，单服务器故障不拖垮回合。工具统一挂 `mcp` capability 走 RBAC 分级，管理员经 `manage_settings` 配置。README 工具体系补充 MCP 说明。
- **pi SDK 升级 0.83.0 → 0.99.1**：破坏面仅 `generateSummary` 签名（signal 移入 chord Context 第 10 参）；压缩与心跳旁路调用改传 `withAbortSignal(signal, BACKGROUND_CONTEXT)`，此前修复的有界中止能力完整保留；新增直接依赖 `@earendil-works/chord` 0.99.1。

### 修复

- **含关键凭据的知识条目拒绝合并，保持独立条目**（现场 2026-09-30：一条「生产环境后台管理地址 + 账号密码」条目被自动整理合并进「对账操作规范」——关键值虽逐字保留，但合并后条目标题/标签是流程主题，其他页面按「后台管理地址」「账号密码」检索时不再匹配，凭据事实上丢失）。双层防护：整理提示词明确含凭据条目不参与 merge；应用 merge 操作时代码级剔除含关键值的条目（不足 2 条则放弃合并），普通合并的逐字回填护栏保留。已被合并的条目可搜新条目取回原值，或在控制台手动拆回。
- **心跳旁路调用放宽到 180 秒**（现场 2026-09-30：最新版本心跳仍是无内容通用行）：60 秒上限在繁忙中继下几乎每次都被中止回落，回落率接近 100%。放宽到 180 秒仍保证 `progressInFlight` 不会永久卡死（挂起最多吞 1 个心跳周期），但给慢中继留足余量。
- **心跳兜底引用最新实质性请求**：兜底原来只引用压缩总结，任务尚未触发过压缩时只能给无内容通用行；此前还把纯应答当任务名（「任务：确认。」）。现兜底分层（全确定性）：压缩总结（策展目标）→ 新增 `substantialAnchorOf`（最新实质性请求，过滤「确认/好的/继续」等纯应答与合成指令）→ 通用行。
- **安装包排除死重，Windows 包回到 100MB 内**（105MB → 96MB）：files 全量通配把构建期依赖也打进了安装包——chord 嵌套的 esbuild 平台二进制（10.5MB，Windows 包里装的还是 darwin 版）、顶层 esbuild/@esbuild（21MB，运行时零引用）、better-sqlite3 的 SQLite 源码（~10MB，运行时只加载预编译 .node）。SDK 升级后包体曾超过 Gitee 单资产 100MB 上限导致 feed 发不出，现已恢复。
