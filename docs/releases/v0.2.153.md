# v0.2.153

## 常驻巡检任务：性质声明 + 模型 DONE 拦截（#92）

### 现场根因

每日对账巡检自主任务被模型在无异常日输出 `[[TASK_DONE]]` 单方面杀死（done 终态无法 reopen，只能重建）。DONE 是模型可单方面输出的最高优先级标记，引擎原先无条件接受——对「持续巡检」类任务，「今天没事」的正确表达是 NEXT_CHECK 降频，而不是宣布任务完成。

### 三层防线

1. **声明**：`manage_work_items create` 加 `resident` 参数——巡检/监控/每日对账类无自然终点任务必须 true（`work_items` 加列，旧库自动迁移，默认一次性）
2. **预防**：常驻任务的工作窗口前缀明确告知模型「没有『全部完成』的一天，禁止 DONE；无异常用 NEXT_CHECK 顺延；只有管理员能 cancel」
3. **拦截兜底**：模型仍输出 DONE → 引擎不落终态，按上次声明节奏顺延（夹紧 1h~7d，未声明过走 24h），推送告知管理员「已自动顺延，确需结束请 cancel」

### 审查修复（独立 code-review 探针实证）

- 默认节奏真值 24h（原实现 NULL cadence 会算成 1h 且文案撒谎——主路径每小时唤醒+推送）
- routine streak 保持语义：引擎顺延不 +1（防冤枉模型「固定时间」）、不清零（模型既有节奏保留）
- 节奏文案 <2h 用分钟；get 输出带「性质：常驻巡检」；DONE 顺延清 fallback 计数

### 使用

重建常驻任务时声明性质（如「重建对账巡检自主任务，**常驻**」），创建后每个窗口受保护。已建成的一次性任务不受影响。

### 测试

+4 resident 用例（拦截/非拦截对照/null-cadence 24h/streak 保持）。52 套件 + typecheck + build + 13 immutable 全过。
