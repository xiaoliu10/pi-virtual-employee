# v0.2.232

## English

- **Widget tool steps render above the answer; empty cursor bubbles are hidden (#216).** The embedded widget created the answer bubble at send time, while tool-call rows were appended after it — so a bordered white bubble showing only the blinking cursor appeared between the thinking text and the tool list, and the final answer landed above the tools. Tool steps now insert before the answer bubble (thinking → tools → answer) in both the floating loader and the standalone page. The answer bubble is hidden while only thinking/tool events have arrived and reappears when real answer text streams in; turns without process events keep the "thinking…" placeholder. Header and footer are pinned with `flex-shrink: 0` so the input area always stays at the bottom of the panel.
- **A discoverable, keyboard-accessible resize grip (#217).** Drag resizing worked but the 9px grey corner mark was effectively invisible (resting contrast ≈ 1.6:1 on white; it only deepened on hover, which users could never discover). The hit area grows from 22×22 to 28×28, the visual mark becomes a two-tier corner chevron with a 13px outer mark in `#76767a` at full opacity (resting contrast ≈ 4.4:1, meeting the 3:1 non-text contrast minimum), and hover deepens it further. Both channels now set `tabindex="0"`, `role="separator"` and `aria-orientation="both"` on the grip, so Tab reaches it, screen readers announce it, and the existing arrow-key resizing (24px per key press) finally works for keyboard users; a visible `:focus-visible` outline is drawn inside the panel to avoid clipping by the panel's `overflow: hidden`.

Validation: all 146 test suites pass on the integrated code (including the new transcript-order and resize affordance/contrast/keyboard regressions; postcss parses every served stylesheet), both TypeScript projects pass, and all 16 immutable regions remain unchanged. Windows x64 and macOS arm64 packages must pass the app.asar integrity gate before publication.

Boundaries: the resize grip's visual language stays a corner chevron — no extra header button or one-time coaching bubble is introduced. Widget layout lives entirely in the loader's shadow DOM; host pages cannot and need not style it. Gitee connectivity was flaky during publication preparation; the release is published through the normal dual-endpoint flow with retry, and the feed is verified independently after upload.

## 中文

- **Widget 工具步骤置于答文之上，并隐藏无正文时的空光标气泡（#216）。** 小组件在发送时预先创建回答气泡，而工具调用行被追加到它后面，导致思考文本与工具列表之间出现一个只剩闪烁光标的白底空框，最终答案也会渲染在工具列表上方。现在浮窗 loader 与独立页两条通道都把工具步骤插入回答气泡之前（思考 → 工具 → 回答）；在只有思考/工具事件、尚无答文时隐藏回答气泡，真正的答文流式到达时再显示；没有过程事件的回合仍保留「正在思考…」占位。顶部栏与底部输入区通过 `flex-shrink: 0` 固定，输入框始终位于面板最下方。
- **缩放抓手可发现、可键盘操作（#217）。** 鼠标拖拽功能本身正常，但原先 9px 灰色折角几乎不可见（白底常态对比度约 1.6:1，且只有悬停才变深，形成「看不见就不会去悬停」的死锁）。热区从 22×22 扩大到 28×28，视觉标记改为双层圆角折角、外层 13px 且常态使用 `#76767a` 全不透明（白底对比度约 4.4:1，满足非文本控件 3:1 下限），悬停进一步加深。两条通道的抓手均补齐 `tabindex="0"`、`role="separator"`、`aria-orientation="both"`，Tab 可以聚焦、屏幕阅读器可朗读，既有的方向键微调（每次 24px）对键盘用户真正可用；焦点描边内缩绘制，避免被面板 `overflow: hidden` 裁切。

验证：集成后全部 146 个测试套件通过（含新增的消息顺序、缩放抓手可发现性/对比度/键盘回归测试，postcss 对每套下发样式表完成解析），两个 TypeScript 项目通过，16 个不可变区域未变。Windows x64 和 macOS arm64 安装包发布前必须通过 app.asar 完整性检查。

边界：抓手视觉语言保持为角标折角，未引入额外顶栏按钮或一次性引导气泡。Widget 布局完全位于 loader 注入的 shadow DOM 内，宿主页无法也无需覆盖其样式。发布准备期间 Gitee 连接存在抖动，发布走既有双端流程并带重试，上传后对更新源做独立校验。
