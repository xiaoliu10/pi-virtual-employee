## 0.2.112

### 新增

- **waiting_human 周期重提醒**（设计拍板：24h 首提 + 24h 间隔；管理员主动暂停同样提醒；proposed 暂不纳入）。此前任务转 waiting_human 后只推一次，管理员没看到就永久沉默——任务实质死亡。现在每个 waiting_human 项按 24h 节奏重推「⏸️ 自主任务仍在等待人工」，带已等待时长 + 原问题摘要 + 处置指引（回复答复继续 / 取消）；第 3 次起措辞升级明确建议二选一。**不自动恢复**（非幂等操作不盲重跑），只是拒绝静默。技术：`last_remind_at`/`remind_count` 列（自动迁移）；`nextWakeAt` 扩展为 MIN(最早 scheduled, 最早提醒期限)——修复「全部 waiting_human 时没有任何定时器」的结构性盲区；提醒按尝试计数（推送失败不空转 tick）；resume/终态自动脱离。
- **延迟感知**：scheduled 窗口实际触发比原定时间晚 ≥30 分钟（应用没开/正忙后补跑）时，窗口前缀注入【延迟说明】——告知原定时间与延迟时长，要求先核查中间时段的新进展/新数据，不要把现在当原定跟进时刻。

### 说明

- resume 清零提醒状态（`last_remind_at`/`remind_count`）；所有重新进入 waiting_human 的转换（runner 收尾、管理员暂停、崩溃恢复）与 setSchedule 改期同样清零——重入是全新一集，陈旧计数会导致改期后秒推过期提醒、升级文案提前到来（复审复现后修复）。完成/取消等终态自然脱离提醒循环。
