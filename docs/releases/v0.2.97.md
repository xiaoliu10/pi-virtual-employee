## 0.2.97

### 修复

- **「自动压缩没腾出空间」实为误判，不再误杀任务**（现场 2026-09-24：SLS 任务报告「已尝试自动压缩仍未通过」被中断）：降级裁剪路径（`truncateToFit`）保留尾部消息时没有剥掉 provider 用量记录——那是裁剪**前**那次请求的数字，估算按它取地板，于是裁剪前后读出同一个数（158293 前、158293 后），闸门复查把实际成功的裁剪判成「还是超」。现裁剪后剥除旧用量，复查量的是真实剩余大小：只要裁剪真的腾出了空间，任务就继续跑。
- **上下文暂停的通知不再谎称任务结束**：旧文案「本次任务在此结束」与事实不符——结束的只是本次执行，定时任务下次触发会从同一会话继续（该任务事后确已完成）。改为「本次执行到此暂停，任务尚未完成」并给出续跑路径（下次触发自动继续；或 `/compact` 后发「继续」）。
- **上下文预算触发暂停时，回合收尾立即强制压缩**：闸门刚证明转录超阈值，收尾的压缩直接 force 执行（链式摘要 + 强制切点），确保任务下次触发开跑即在预算内——上下文接近上限的处理方式是自动压缩后继续，停止任务从来不是方案。
- **心跳进度不再引用内部提示词**（现场 2026-09-24：长任务心跳把「现在请不要调用任何工具，直接用一段简明的中文总结：…」原样当任务名发给了用户）：收尾总结指令以合成 user 消息形式留存在会话里，压缩后可能被当成「第一个用户消息」。现进度汇报与旁路总结切片均识别并跳过该合成消息，转录中只剩它时回退到不含任务名的通用文案，绝不引用指令原文。
