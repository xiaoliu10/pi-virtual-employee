# v0.2.230

## English

- **Independent chat and unattended progress intervals (#210).** Inline chats and chat-dispatched workers use `longTaskProgressMin`; scheduled runs and autonomous work windows use `taskProgressMin`. A worker moving into background execution keeps its chat cadence. The global progress pump reads both settings independently, supports disabling/re-enabling either cadence, and logs the selected interval.
- **Worker progress reaches its source chat (#210).** Resolve internal worker conversations to their persisted source before delivery and ledger recording. The pump advances its last-success timestamp only after an acknowledged successful delivery; failed or missing acknowledgements are logged and remain eligible for retry.
- **Restore all running profiles after updates (#211).** Accept Windows WMIC CRCRLF output when collecting running profiles, so the update watchdog retains the complete recovery list instead of falling back to only its own profile.
- **Keep completed-worker follow-ups topical (#212).** An unrelated message sent long after a worker finished returns to chat triage with conversation context. Related follow-ups still reach the worker that performed the task; classifier failures preserve continuation.
- **Realtime lookup guidance belongs to the tool (#213).** `research_web` now describes its static-search boundary and directs weather, exchange-rate, stock-price and similar requests to browser tools and authoritative pages, including in empty-result messages.
- **Acknowledged human requests during autonomous work (#214).** Add `manage_work(action=request_human)` to notify the source IM conversation during a work window. Only successful delivery spends the per-item 30-minute notification budget; concurrent duplicates are guarded. Note-taking actions explicitly state they do not send messages. Remove conflicting SMS-code instructions and direct the window to request help, avoid repeated SMS sends and close with `[[NEED_HUMAN]]` while awaiting input.

Validation: all 145 test suites pass on the integrated code, both TypeScript projects pass, and all 16 immutable regions remain unchanged. Windows x64 and macOS arm64 packages must pass the app.asar integrity gate before publication.

Boundaries: progress intervals are scheduling intervals, with polling and model-generation latency; they are not exact delivery deadlines. Existing notifiers retain the interval captured at creation; subsequent runs use the corrected wiring. The independent notifier and pump paths are not deduplicated against each other. Human-request throttling is process-local; the existing closing notification remains. Concurrent profile installation still has no machine-wide installer lock. A live SMS-code round trip and live timed progress delivery are separate deployment checks, not implied by the test results.

## 中文

- **聊天与无人值守进度间隔独立（#210）。** 直接聊天和聊天派发的 worker 使用 `longTaskProgressMin`；定时任务和自主任务工作窗口使用 `taskProgressMin`。聊天任务转到后台 worker 执行后仍保持聊天节奏。全局进度 pump 独立读取两项设置，支持分别关闭和重新开启，并记录所选间隔。
- **worker 进度送回来源聊天（#210）。** 投递和记录台账前，通过持久化映射把内部 worker 会话解析为来源聊天。pump 只有收到成功投递回执才更新时间戳；失败或缺少回执会留日志，并保留重试资格。
- **升级后恢复全部运行中的 profile（#211）。** 采集运行实例时兼容 Windows WMIC 的 CRCRLF 输出，更新看门狗保留完整恢复名单，不再退化为只恢复自己。
- **已完成 worker 的追加消息按主题归属（#212）。** worker 完成很久后收到的无关消息返回聊天分诊，并携带对话上下文；相关追问仍回到执行原任务的 worker，分类失败保留继续执行的行为。
- **实时查询引导放在工具自身（#213）。** `research_web` 明确静态检索边界，对天气、汇率、股价等请求指向浏览器工具和权威页面；空结果返回也提供相同引导。
- **自主任务轮内可确认送达的人工请求（#214）。** 新增 `manage_work(action=request_human)`，在工作窗口中向来源 IM 会话请求协助。只有成功投递才消耗单任务 30 分钟通知额度，并防止并发重复发送。笔记动作明确说明不发送消息。删除相互冲突的短信验证码指令，要求请求协助、避免重复发送短信，并以 `[[NEED_HUMAN]]` 收尾等待输入。

验证：集成后全部 145 个测试套件通过，两个 TypeScript 项目通过，16 个不可变区域未变。Windows x64 和 macOS arm64 安装包发布前必须通过 app.asar 完整性检查。

边界：进度间隔是调度间隔，包含轮询和模型生成延迟，不是精确送达期限。已有 notifier 保持创建时捕获的间隔，后续运行使用修正后的接线。独立 notifier 与 pump 尚未跨链去重。人工请求节流仅在进程内有效，现有收尾通知保留。并发 profile 安装仍未设置机器级安装锁。真实短信验证码往返和真实定时进度送达属于独立现场验收，不能由测试结果推定。
