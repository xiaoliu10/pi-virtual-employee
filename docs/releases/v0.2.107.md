## 0.2.107

### 改进

- **自主任务跟进节奏：完全由执行结果动态决定，不约定频率**（#23，现场定位：自主任务更像闲时任务，但闲时不是主要触发途径——夜里虽闲，三方卡点不会在夜里解决）。工作窗口的 `NEXT_CHECK` 协议重写为动态规则：
  - **有卡点先问清 ETA**：等第三方补数据、等对方处理、等资源，且不确定何时解决 → 不盲目定时重试，先 `[[NEED_HUMAN]]` 把问题抛到来源会话（如「这个卡点大概什么时候能解决？」），按答复定下次跟进时间；
  - **时间常识**：深夜/非工作时间对接方通常不处理，不空查，把跟进推到对方可能处理的时间；
  - **按观察点查**：数据何时生成、批次何时跑完、何时出结果，就在那些时刻查，一天可以多次（如 09:00 查昨日历史、12:30 查今日上午批次、15:00 查今日下午）；
  - 首个窗口的跟进计划要求写明「卡点找谁问、问什么」。
  - 机制零变更：`NEXT_CHECK`（本次结果定下次）、`NEED_HUMAN`（暂停并抛问题）、管理员「确认继续」附答复恢复——链路 0.2.106 已就位，本版把判断规则写全。
- **恢复指引修正**：任务需要人工时的推送指引从「继续 <标题>」改为「**确认继续** <标题>」——恢复门禁要求当前消息包含「确认」，旧文案照抄会被拒一次。

### 升级后建议

- 若现场有「固定时刻 + 自主模式」的定时任务承载本应动态跟进的目标（如对账巡检），建议取消并改用工作项：首窗先列观察点计划，之后每次跟进按「批次何时跑完、卡点何时解决」动态定时间。
