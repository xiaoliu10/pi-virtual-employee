# v0.2.195

## English

### Desktop composer is resizable

The 0.2.193 resize covered the **embedded widget** only — the desktop app's chat input stayed `resize-none` with a fixed height floor, so there was nothing to drag in the window users actually work in. Fixed.

- Drag the strip along the top edge of the input card to make it taller; dragging up grows it.
- The height is remembered across restarts; double-click the strip to restore the default.
- Clamped twice: absolute 56–420px, and never taller than the window allows (240px is always reserved for the transcript). Shrinking the window re-clamps automatically, so the message list can never be squeezed out.

### Quality

- The clamping/drag math lives in a pure module (`lib/composer-height.ts`, same convention as `sidebar-width.ts`) and is covered by 5 assertions — including the classic trap where `Number(null) === 0` would silently collapse a missing stored value to the minimum instead of the default.
- 4 mutation rounds red (null fallback, viewport ceiling, missing drag handle, fixed-height regression).
- 112 test suites green; immutable core (16 regions) unchanged.

## 中文

### 桌面端输入框可拖拽调整高度

0.2.193 的拖拽 resize 只做在**网页嵌入式小组件**上，桌面应用的聊天输入框一直是固定高度、禁止 resize，所以在用户真正使用的窗口里根本找不到拖拽入口。现已修复。

- 拖动输入卡片顶部的横条即可加高（向上拖变大）。
- 高度会记住，重启后保留；双击横条恢复默认高度。
- 双重夹取：绝对范围 56–420px，且不超过窗口可用空间（始终给消息区留 240px）。窗口缩小时自动回夹，聊天记录不会被挤没。

### 质量

- 夹取与拖拽计算抽到纯模块（`lib/composer-height.ts`，与 `sidebar-width.ts` 同约定），5 条断言覆盖——包括 `Number(null) === 0` 把「缺失存储值」误夹到最小值而非默认值的经典坑。
- 变异 4 组全红（null 回落、视口上限、缺抓手、退回固定高度）。
- 112 个测试套件全绿；不可变内核（16 区）未动。
