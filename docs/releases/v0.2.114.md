## 0.2.114

### 改进

- **知识库优先于问人（KB-first）**（现场 2026-10-04：登录失效后知识库里明明有正确账号，员工却直接问管理员「该用哪个账号」，管理员提示后才去查库）。自主窗口协议三处强化：
  - **问人前置义务**：`[[NEED_HUMAN]]` 之前必须先 `search_knowledge_base` 查一遍（账号密码/地址入口/操作流程/规则大概率已有沉淀），问题里必须写明「已查知识库（关键词 X），未找到」及已尝试的办法——让管理员一次给准信；
  - **登录过期不再直接问人**：旧文案「登录过期直接 NEED_HUMAN」在主动跳过知识库，现改为先搜「系统名 + 登录/账号」找新账号密码或登录指引，找得到就自己重登继续，确实没有才升级；
  - **解决后回写**：卡点解决后把可复用信息（正确账号、新流程、报错根因）用 `save_to_knowledge` 沉淀进知识库，下次同类卡点直接查库；首窗计划的卡点部分同步要求写明「这类卡点先查知识库搜什么关键词」。
- **自主链同步 KB-first**（复审抓出）：`autonomous.ts` 的链式协议同样有「卡住了必须问人（缺账号…）」「登录过期直接 NEED_HUMAN」两条旧文案——现场 16:30 的自主任务走的正是这条链。同步改为 KB-first（先查 `search_knowledge_base`、登录过期先搜库自己重登），与工作窗口协议口径一致；知识库关闭时自动退回旧措辞，不引用不存在的工具。
- **工具门控条件化**：知识库学习默认关闭（`kb.learn.enabled=false` → 无 `save_to_knowledge` 工具），回写指引按 `kbFeatures` 实际门控条件化，避免引用幽灵工具每次烧一轮 LLM 往返。副产品：KB-first 查库未命中会自动 `recordGap()`，反复卡点会浮出为知识缺口，管理员可见。
- **合理豁免**：明显只有人能当场提供的信息（验证码、口头确认、对方答复）免查知识库，但问题里要写明为什么没查——防止模型为满足格式编造「已查无果」。
