# v0.2.227

## English

### Work-item titles are sanitized — the compaction template never becomes a task name

Field 2026-11-11: a progress note pushed to the group as「⏳ **## Goal
- 继续排查流水 0342026111100001174 …** 任务仍在进行中」. The model had passed the compaction summary's `## Goal` section **verbatim** as a `manage_work_items` create title (`p.title.trim().slice(0, 80)` accepted anything), and the progress broadcaster echoed the stored title verbatim. The four-field note BODY was fine (existing `progress.ts` defenses held) — only the title chain was dirty.

v0.2.227 adds `sanitizeWorkItemTitle()` and wires it at three layers:

- **Ingestion** — create/derive titles in `work.ts` are sanitized before they are stored (limit 80), and the admin-create `originNote` (limit 120): this fixes NEW rows.
- **Broadcast** — `progress-notify.ts` sanitizes the title at the last hop before the user sees it (limit 40): this cleans EXISTING contaminated rows without a migration.
- The bold prefix is dropped entirely when the sanitized title degrades to the placeholder 「未命名任务」.

The sanitizer is stricter than it looks, because two independent review rounds found that the obvious implementations leak:

- A **single pass** misses wrapped shapes — `**## Goal** 排查`、`> ## Goal`、`- ## Goal` all keep their `#` because the wrapper sits at the string head when the heading strip runs.
- A **string-anchored loop** stops at the first ordinary line — a template heading on a LATER line (`排查日志\n## Goal\n- 继续排查`) survived flattening into the displayed title, at every limit (40/80/120) and through the real notifier.

The shipped version strips inline emphasis first, then strips each line's leading decorations (template Goal heading with any casing/spacing/colon, any markdown heading, bullets, blockquotes, and decoration-only lines) to a per-line fixpoint, then flattens. Mid-line markers survive (`排查 > 继续 - 内容` unchanged, `1. 步骤`/`-5 度`/links/RTL untouched). All whitespace collapses to single spaces, long titles clamp at a clause boundary, and a fully contaminated title degrades to 「未命名任务」 instead of shipping garbage.

Verification: 3 independent review rounds (round-1: 4 confirmed leaks, fixed; round-2: REQUEST CHANGES on later-line headings, fixed; round-3: **PASS** — 45-probe idempotence × 3 limits zero violations, real-notifier end-to-end clean, adversarial corpus no new leaks, one P3 degenerate-input regression found and fixed). 141 test suites pass (sanitize 9 + progress-notify 24), both typecheck projects clean, immutable-kernel gate reports 16 guarded regions unchanged.

## 中文

### 任务标题消毒——压缩模板不再变成任务名

现场 2026-11-11：一条进度汇报以「⏳ **## Goal
- 继续排查流水 0342026111100001174 …** 任务仍在进行中」推进群里。模型把会话压缩总结的 `## Goal` 段**原样**填进了 `manage_work_items` 的创建标题（`p.title.trim().slice(0, 80)` 来者不拒），进度广播又把库里存的标题原样输出。正文四字段（`progress.ts` 既有防线）正常——脏的只有标题链路。

v0.2.227 新增 `sanitizeWorkItemTitle()` 并在三层接线：

- **入库**——`work.ts` 的 create/derive 标题入库前消毒（限 80），管理员直接创建的 `originNote`（限 120）：治新。
- **推送**——`progress-notify.ts` 在用户可见的最后一跳消毒（限 40）：不动库就能清洗存量脏行。
- 消毒后退化成占位符「未命名任务」的标题，直接省掉加粗前缀。

这个消毒器比看上去难写，因为两轮独立评审证明想当然的实现都会漏：

- **单遍剥离**漏包裹形态——`**## Goal** 排查`、`> ## Goal`、`- ## Goal` 都会留下 `#`，因为包裹符还在串首时标题剥离根本不生效。
- **锚定整串的循环**在第一行普通内容处就停——后面行里的模板标题（`排查日志\n## Goal\n- 继续排查`）照样被拍平进展示标题，40/80/120 三个限额全部复现，真实通知器端到端同样复现。

最终版本先剥行内强调符，再对每一行做行首装饰（模板 Goal 标题含任意大小写/空格/冒号、任意 markdown 标题、列表符、引用符、纯装饰行）的定点剥离，最后拍平。行中标记不动（`排查 > 继续 - 内容` 原样保留，`1. 步骤`/`-5 度`/链接/RTL 不受影响）。全部空白折叠为单空格，超长标题在从句边界截断，完全污染的标题退化为「未命名任务」而不是把垃圾推给用户。

验证：3 轮独立评审（第 1 轮确认 4 处泄漏已修；第 2 轮 REQUEST CHANGES 指出后行标题残留已修；第 3 轮 **PASS**——45 探针 × 3 限额幂等零违例、真实通知器端到端干净、对抗语料无新泄漏、1 处 P3 退化输入回归已修）。141 套件全过（sanitize 9 + progress-notify 24）、双 typecheck 零错、不可变内核闸门报告 16 守护区未变。
