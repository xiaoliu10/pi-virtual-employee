# v0.2.215

## English

### Workers are born with the conversation they came from

Field incident (2026-11-10, single chat): the user sent a bare 「875055」 — a number the chat had contextualized turns earlier — and the router injected it into the most recent worker. A worker is born with its instruction only, so it guessed "order system", found nothing, and asked the user what the number was. Three changes close this class:

- **Worker spawn carries the source conversation** (`feat/worker-source-context`): the dispatch turn is prefixed with a bounded excerpt of the originating chat — tail-aligned 24 messages / 10k chars / 500 per message, synthetic delivery notices filtered, entries forging block markers (`【任务指令】` etc.) dropped (indirect prompt injection, review 0bcb32c4), read via a bounded tail query. With no excerpt the message is byte-identical to before; follow-up turns are never re-prefixed. Partition law: same conversation only — a group worker sees the group stream (soft isolation, user ruling 2026-11-10).
- **Bare context tokens never reach a context-less worker** (`fix/bare-token-inject-guard`): a bare alphanumeric token (code/serial/order id/UUID ≤64 chars, trailing CJK punctuation stripped) sent into a DONE/CANCELLED worker falls through to the foreground, which holds the chat history. One implementation shared by the inject gate and the triage router (`reason=reference`) — the manager's planless dispatch cannot loop the token back into a freshly spawned worker (review 7ba60092 P1). LIVE workers still receive everything unconditionally (the verification-code handoff contract).
- **Plan ETAs are honest** (`fix/plan-eta-rigor`): a plan without a reliable basis must say 「不确定」 — hedged lines like 「不确定，最多30分钟」 no longer leak the embedded number into the ≥30-minute chat-push gate, and uncertain plans stay dispatchable.

### Safety moved from prompt text into tools

The field incident behind this release: a leftover debug script (`kill_pw_chrome.ps1`) indiscriminately killed every Playwright browser — including the one executing a live spay login — twice in a row. A skill teaches; it cannot enforce. This release makes the enforcement structural:

- **`manage_process scan → kill_pid` two-phase kill** (`feat/process-hygiene-tools`): `scan` enumerates matching processes and computes the four holding criteria IN CODE — debug channel (**`--remote-debugging-port` or `--remote-debugging-pipe`**: Playwright's Chromium defaults to pipe; a port-only check misses every long-lived session), parent-alive (the driver), age (threshold must exceed the task contract), contract registry. Killing requires a fresh ticket and re-verifies identity (exe + start time) at kill time, so PID reuse cannot launder the target. `kill_pid` carries the same admin-grade confirm gate as the existing kill, and both shell tools are wrapped in `guardAll("shell")` so RBAC capability floors apply.
- **Execution gate**: `run_command`/`run_script` scan the command text AND the script file content (`.ps1/.sh/.py/.js/.mjs/.cmd/.bat`) for indiscriminate-kill shapes — the field form (`powershell -File kill_pw_chrome.ps1` is invisible on the command line) is refused with a why and a how, every refusal audited. Sensitive-file entries are hidden from listings.
- **「运维脚本」 skill** (`feat/ops-script-safety`): the four iron laws (targets first / dry-run by default / holding check / contract registry) with copy-ready PowerShell and Bash templates, merged with the Windows syntax-pitfall handbook (quoting hell, GBK garble, parameter passing, background tasks). Independent review hardened it with real probes: Playwright's pipe default, per-process exception guards, Linux orphan (ppid=1) semantics, atomic contract writes.
- **Filesystem gate fixes** (`fix/fs-list-sensitive-dirs`): listing a sensitive dir is allowed again — a user-imported skill with bundled scripts had become undiscoverable — while writes/deletes keep the deny-list; a pre-existing hole was sealed on the way (a workspace junction could launder `delete_files` past the deny-list and remove the real profile `config.json`; destructive paths now resolve realpath, fail-closed); sensitive-file entries are hidden from listings.

### Memory routing: teaching is shared knowledge, not a personal preference

The three memory scopes (person / conversation / profile-shared) already existed; the gap was routing. `remember` now carries a routing iron law and the prompt guidance states it explicitly: when someone teaches the assistant HOW to do something (admin-console usage, reconciliation handling, script patterns), that is shared knowledge — it goes to `save_to_skill` / `save_to_knowledge` so every session benefits. Person-isolated memory only holds that person's preferences, corrections and environment.

### Design record

`docs/design/router-worker-core.md` remains the architecture baseline; the memory three-tier ruling (person-habit / conversation / system-operation shared) and the soft-isolation amendment are queued for the RouterSession phase (PR-4).

## 中文

### Worker 出生即携带来源会话

现场（2026-11-10 单聊）：用户发裸「875055」——编号类型上文早已确立——路由器把它注入了最近的 worker。worker 出生只带指令文本，只能猜「订单系统」，没查到，反问用户「这是什么类型的编号」。三项改动封死这一类：

- **worker 派发携带来源会话**：首回合前置有界摘录——尾部对齐 24 条 / 10k 字符 / 单条 500，过滤合成兜底通知，丢弃伪造块标记（`【任务指令】` 等，间接提示注入），有界尾读。无摘录时消息逐字节不变；跟进回合绝不重复前置。分区铁律：只取来源会话——群 worker 拿群流（软隔离，用户裁定 2026-11-10）。
- **裸上下文标记永不进入无上下文 worker**：裸字母数字标记（验证码/流水号/单号/UUID ≤64 字符，剥尾部中文标点）进入已完结 worker 时落回带完整聊天历史的前台。inject 门与 triage 路由共享同一实现（`reason=reference`）——manager 的 planless dispatch 无法把标记环回成新 worker。LIVE worker 仍无条件接收（验证码流转契约）。
- **计划耗时诚实化**：没有可靠依据必须写「不确定」——「不确定，最多30分钟」这类对冲行不再把内嵌数字漏进 ≥30 分钟推卡门，不确定的计划保持可派发。

### 安全从提示词文字降级为内置工具

本版本的现场背景：一个调试残留脚本（`kill_pw_chrome.ps1`）无差别杀掉所有 Playwright 浏览器——连正在执行 spay 登录的那个一起，连杀两次。技能能教，不能强制。本次把强制做成结构：

- **`manage_process scan → kill_pid` 两段式杀**：`scan` 枚举匹配进程，四项持有判据在代码里算好——调试通道（**port 或 pipe**：Playwright 的 Chromium 默认 pipe，只查 port 会漏掉全部长会话）、父进程存活（driver）、年龄（阈值必须大于任务契约）、契约台账。杀需要新鲜票据并在杀前重验身份（exe + 启动时间），PID 复用无法洗白目标。`kill_pid` 带与既有 kill 相同的管理员级确认门，两个 shell 工具包进 `guardAll("shell")`，RBAC 能力门槛生效。
- **执行闸**：`run_command`/`run_script` 扫命令文本与脚本文件内容（`.ps1/.sh/.py/.js/.mjs/.cmd/.bat`）的无差别杀形态——现场形态（`powershell -File kill_pw_chrome.ps1` 在命令行上不可见）被拒并附原因与做法，每次拒绝落审计。列举结果隐藏敏感文件条目。
- **「运维脚本」技能**：四条铁律（目标先行/默认演练/持有检查/契约登记）+ 可直接抄写的 PowerShell 与 Bash 模板，合并了 Windows 语法坑手册（引号地狱、GBK 乱码、参数传递、长任务后台化）。独立 review 用真实探针加固：Playwright 的 pipe 默认值、逐进程异常兜底、Linux 孤儿（ppid=1）语义、契约原子写。
- **文件系统门禁修复**：敏感目录重新可列举——带捆绑脚本的用户导入技能曾因此完全不可发现——写/删保持拒入；顺带封堵一个预存漏洞（工作区内 junction 可让 `delete_files` 绕过拒入清单删掉真实的 profile `config.json`；破坏性路径现在解析 realpath，fail-closed）；列举结果隐藏敏感文件条目。

### 记忆路由：教学是共享知识，不是个人偏好

三层记忆 scope（person / conversation / profile 共享）早已存在，缺的是路由。`remember` 现在携带路由铁律，提示词指引同步明示：对方教「怎么做某事」（后台管理用法、对账处理、脚本写法）是共享知识——进 `save_to_skill` / `save_to_knowledge`，让所有会话受益。按人隔离的记忆只装这个人的偏好、纠错与环境。

### 设计记录

`docs/design/router-worker-core.md` 仍是架构基线；记忆三层裁定（个人习惯 / 会话 / 系统操作共享）与软隔离修订已排入 RouterSession 阶段（PR-4）。
