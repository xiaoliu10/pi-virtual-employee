# v0.2.162

发布时间：2026-10-27。单功能版本：**定时任务长任务执行期周期性进度推送**（PR #109）。

## 定时任务进度推送

单轮定时任务（最常见形态）执行最长可达 60 分钟（硬超时），此前执行期间**零推送**——群里看不到"还活着"的信号，只能等最终报告落地。自主链在 v0.2.72 已有心跳旁路总结，本版把缺口补上。

- **复用旁路总结机制**：`engine.progressBrief`（side LLM pass，不写 transcript、不占上下文、180s 有界、计入看门狗存活），失败回落确定性四段兜底（已完成/剩余/正在/卡点）
- **每 15 分钟一拍**（`general.longTaskProgressMin`，0=关闭；低于 5 按 5 生效；已显式设置的实例不受默认值变化影响）
- 备注带任务名：`⏳ **任务名** 已完成：… 剩余：… 正在：… 卡点：…`（同群多任务可区分归属）
- 完成时自动停播：`stop()` 后 `drain(5s)` 等在途推送落定，再发完成报告——「⏳ 进行中」不会晚于「定时任务完成」到达
- 静默任务保持静默（进度同样不推，且不烧旁路 LLM 调用）
- 超时放弃的 losing run 不再播报（与调度器的失败记录保持一致）
- 中继挂掉时指数退避（最多 2 条「暂未确认」空壳，封顶 60 分钟），恢复后自动清零

## Review 过程

独立 review（真实引擎/真实 ConfigStore 探针）：无 P1；2 P2 + 4 P3 全部修复——

- P2-1 推送倒挂（慢推时进度晚于完成报告）→ `drain` 机制
- P2-2 losing-run 竞争窗口（suppress 中翻转）→ push 前复查
- P3-1 silent 任务白烧 LLM → `preflight` 静态门前移
- P3-2 备注无任务名 → 标题进前缀
- P3-3/4 注释诚实化、hint 补下限

19 用例（mock timers 分步推进）+ 4 mutation 全部可检出。Copilot 因 quota 未审（本批一贯状态，独立 review + mutation 替代）。
