## #108 记忆召回重构

记忆注入从「按 recency 全量倒出」改为「相关性召回」，核心目标是**避免过量记忆污染上下文**（用户原话：「检索是关键」）。

- 双闸门准入：语料内 token 区分度锚点（`tokenSpecificity(df,N)=(N-df)/(N-1)` ≥ 0.5）+ IDF 加权覆盖率 ≥ 0.12；单命中还须覆盖 ask ≥ 30%
- 提问作用域：粘贴日志/堆栈后只按尾部「真正在问的句子」评分；按行回扫跳过帧/日志行
- memory 与 knowledge 分路召回（`kindFilter` 下推 FTS/LIKE/vector）再按配额合并，知识保底 1 位
- 写入期提示：标题近似冲突、短期事实、祈使句措辞
- **取舍（用户确认）：宁可漏，不可污染**——单通用词重合不召回；同义表达漏召待向量召回方案另议
- 新增 `test-memory-recall`（24 用例）+ `test-knowledge-quota`（10 用例，真实 trigram FTS/向量路径）；6 个 mutation 全部可检出

## #103 更新检查卡死「检查中」

现场 0.2.153 客户端因一次无响应检查把 `checking` 永久置 true，按钮卡死数天。

- `CHECK_TIMEOUT_MS`（默认 90s）硬墙钟 + `finally` 无条件复位
- retry 调度移到窗口关闭后（防止重叠打穿有界计数）
- **zombie 事件全门**：deadline 放弃的检查迟到吐出的事件不得改下载/安装意图；`checking-for-update` 也纳入门控（review P2-1：无门会重新卡死按钮）
- **自动下载改 per-call promise 驱动**（review P2-2）：electron-updater 事件无 owner 标识，跨窗口僵尸在原理上无法用布尔区分；per-call 局部 `windowAlive` 归属精确
- `stopUpdater` 短路在飞检查的 deadline 与 retry（review P3，双层防护）
- 新增 10 用例（含真实 `dispatchError` 时序复刻）；3 个 mutation 可检出

## #104 无人值守任务链身份继承

定时任务运行中代建的跟进任务此前 `created_by` 为空（0.2.63「防权限传递」设计的前提已被 main.ts 重挂 senderId 改变），到点跑不了 `run_command`。

- 调度器 actor 带 `senderId` 时 `createdBy = senderId`、`createdChannel = "scheduler"`，沿用任务链源头创建人的身份（非提权：RBAC 按该真人实时角色）
- 防失控护栏：每创建人名下调度器代建且 enabled 的任务上限 20（`SPAWNED_TASK_CAP`），禁用不占额，超限拒绝不落库
- 真遗留链（无 senderId）行为不变；`authorize_scheduled_task` 回归本职
