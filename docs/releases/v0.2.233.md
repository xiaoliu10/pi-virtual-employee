# v0.2.233

## English

- **ACP (Agent Client Protocol) Streamable HTTP transport (#218).** The employee can now be driven by external ACP clients (Synapse) over the standard agent protocol: a dedicated loopback listener (config `acp.port`, default 17890, bound to 127.0.0.1 only) serves `initialize` / `session/new` / `session/prompt` / `session/cancel` under `/acp`, gated by a Bearer token compared in constant time — an empty token refuses to start the service (open-relay guard). Engine process events translate live to ACP `session/update` notifications (text/thinking deltas → message/thought chunks, tool start/end → tool_call/update), `session/cancel` maps to `abortSession`, and stop reasons map to `end_turn` / `refusal` / `cancelled`. A settings-page card manages the switch, port, token generation and the service account; the `acp` config section deep-merges into existing stores.
- **The ACP trust boundary is structural, not advisory.** ACP session ids are forced to the `acp:` prefix and `inferConversationOrigin` records them as a new remote origin `"acp"` — they can never fall into the bare-uuid console origin whose no-actor path grants implicit admin; the origin is persisted eagerly at `session/new` (`ensureAcpConversation`) before any turn. Every ACP turn executes as ONE fixed service-account actor (`acp.actorStaffId`, default `acp-synapse`, channel `acp`) whose role resolves through the standard `security.people` RBAC path — ACP never asserts `verifiedRole` (that remains widget-only), and no immutable RBAC region is touched.

Validation: all 147 test suites pass on the integrated code, including 6 new ACP transport tests that drive the real `@agentclientprotocol/sdk` client over a real HTTP listener (origin regression guard, empty-token refuse-to-start, wrong-Bearer 401, unknown-path 404, a full initialize→new→prompt→updates→cancel turn with the fixed actor asserted, and engine-error → `cancelled` mapping). Both TypeScript projects pass, all 16 immutable regions remain unchanged, and Windows x64 / macOS arm64 packages must pass the app.asar integrity gate before publication.

Boundaries: loopback only — the listener is never exposed beyond 127.0.0.1. v1 has no in-ve `request_permission` hook: the service account is expected to be granted its role in People management (admin/operator to run shell), interactive approval stays with the ACP client before a prompt is sent, and all shell execution still writes `shell-audit.log`. The path gate matches the `/acp` prefix, so `/acpXXX` aliases reach the same handler — still behind the token + loopback gates, behaviorally identical. The repository's pre-existing package-lock drift (HEAD `npm ci` out-of-sync before this PR) is untouched: this release adds only the 16-line `@agentclientprotocol/sdk` lock increment.

## 中文

- **ACP（Agent Client Protocol）Streamable HTTP 传输（#218）。** 本员工现在可以被外部 ACP 客户端（Synapse）以标准 agent 协议驱动：独立本机监听（配置 `acp.port`，默认 17890，仅绑定 127.0.0.1）在 `/acp` 路径下提供 `initialize` / `session/new` / `session/prompt` / `session/cancel` 全套方法，由 Bearer 令牌把门且以常量时间比较——令牌为空则服务拒绝启动（开放中继防护）。引擎过程事件实时翻译为 ACP `session/update` 通知（文本/思考增量 → message/thought chunk，工具开始/结束 → tool_call/update），`session/cancel` 映射 `abortSession`，停止原因映射 `end_turn` / `refusal` / `cancelled`。设置页新增卡片管理开关、端口、令牌生成与服务账号；`acp` 配置段以 deepMerge 兼容既有配置库。
- **ACP 信任边界是结构性的，不是提示性的。** ACP 会话 id 强制 `acp:` 前缀，`inferConversationOrigin` 将其记录为新的远程 origin `"acp"`——绝不会落入裸 UUID 的 console origin（其无 actor 路径会授予隐式 admin）；origin 在 `session/new` 时即被预落库（`ensureAcpConversation`），先于任何回合。每个 ACP 回合以固定服务账号 actor 执行（`acp.actorStaffId`，默认 `acp-synapse`，channel `acp`），其角色走 `security.people` 标准 RBAC 解析——ACP 绝不自证 `verifiedRole`（该通道仍仅限 widget），且不触碰任何不可变 RBAC 守卫区。

验证：集成后全部 147 个测试套件通过，其中含 6 项新增 ACP 传输测试——用真实 `@agentclientprotocol/sdk` 客户端驱动真实 HTTP 监听（origin 回归守卫、空令牌拒启、错误 Bearer 401、未知路径 404、完整 initialize→new→prompt→updates→cancel 回合并断言固定 actor、引擎异常 → `cancelled` 映射）。两个 TypeScript 项目通过，16 个不可变区域未变，Windows x64 / macOS arm64 安装包发布前必须通过 app.asar 完整性检查。

边界：仅本机回环——监听永不暴露到 127.0.0.1 之外。v1 不做 ve 内 `request_permission` 钩子：服务账号需在「人员管理」登记并授予角色（跑 shell 需 admin/operator），交互审批由 ACP 客户端在发出 prompt 前完成，所有 shell 执行仍写 `shell-audit.log`。路径门按 `/acp` 前缀匹配，`/acpXXX` 别名可达同一 handler——仍在令牌 + 回环双重门禁之后，行为完全一致。仓库既有的 package-lock 漂移（本 PR 之前 HEAD 上 `npm ci` 即报不同步）未被触碰：本版仅新增 `@agentclientprotocol/sdk` 的 16 行 lock 增量。
