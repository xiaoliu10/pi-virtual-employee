# v0.2.194

## English

### Fixed: the 0.2.193 upgrade failed on the cloud box

The box stayed on 0.2.191 with `pending install 0.2.191 -> 0.2.193 FAILED`. Watchdog log:

```
phase1: rename of old install dir failed (locked?) — installing in place: access denied
phase1: silent install exited code=2
```

Restart Manager identified the holder: **the app's own process**, holding all three `resources\app.asar` copies (including two months-old `.old-*` backups). Phase1 terminated the instance with `Stop-Process -Force`, which kills the MAIN process only — Electron's renderer/gpu/utility children outlive it briefly and keep the file mapping alive. Two seconds later the directory rename is refused, so NSIS falls back to the in-place path and exits 2.

Three fixes in the watchdog:

1. **Kill the process tree** — `taskkill /pid <pid> /t /f` per instance, with a per-PID `Stop-Process` fallback only when the tree kill somehow leaves the main process alive.
2. **Drain wait** — poll up to 15s for the exe set to empty instead of guessing a fixed 2s sleep.
3. **Retry the rename** — up to 3 attempts, 3s apart. One transient hold no longer drops onto the wedging in-place path; a genuinely locked directory still falls back and logs the final reason.

### Quality

- The watchdog script is now built by an exported pure function (`buildWatchdogScript`), so its contract is testable without launching an installer: 4 new assertions covering tree-kill, drain, rename retry, and that phase0a / silent-install / wedge-detection / rollback / profile-relaunch survived untouched.
- 3 mutation rounds red (revert to main-process-only kill, drop retry, drop drain).
- 111 test suites green; immutable core (16 regions) unchanged.

## 中文

### 修复：0.2.193 在云盒子上升级失败

盒子停在 0.2.191，记录 `pending install 0.2.191 -> 0.2.193 FAILED`。watchdog 日志：

```
phase1: rename of old install dir failed (locked?) — installing in place: 访问被拒绝
phase1: silent install exited code=2
```

Restart Manager 定位到占用者：**应用自己的进程**，同时持有三份 `resources\app.asar`（含两个 9 月的 `.old-*` 备份）。phase1 用 `Stop-Process -Force` 只杀主进程——Electron 的 renderer/gpu/utility 子进程在主进程死后短暂存活并保持文件映射，2 秒后 rename 被拒，NSIS 退回原地安装并以 code=2 退出。

watchdog 三处修复：

1. **杀进程树** —— 按实例 `taskkill /pid <pid> /t /f`；仅当树杀后主进程仍活着才用逐 PID `Stop-Process` 兜底。
2. **等待清空** —— 最多轮询 15 秒等 exe 集合排空，替代固定 2 秒猜测。
3. **rename 重试** —— 最多 3 次、间隔 3 秒。一次瞬时占用不再直接掉到会卡住的原地安装路径；真正被锁仍会回退并记录最终原因。

### 质量

- watchdog 脚本改由导出的纯函数 `buildWatchdogScript` 构造，契约可在不启动安装器的前提下测试：新增 4 条断言覆盖进程树杀、drain、rename 重试，以及 phase0a / 静默安装 / 卡死检测 / 回滚 / profile 重启未被误改。
- 变异 3 组全红（退回只杀主进程、去掉重试、去掉 drain）。
- 111 个测试套件全绿；不可变内核（16 区）未动。
