# 0.2.144（2026-10-10 发布）

## 变更一：steer 中途转向——长任务跑不停时，取消消息能送进去了（PR #69，现场驱动）

- 现场问题：一个大任务长时间运行，用户发「取消任务」被每会话严格串行队列排在任务后面**永远进不去**；`/stop` 能硬中断但要用户知道命令，且会丢掉整个回合；
- 实现 pi 式 steer：`/steer <内容>` 命令 + 流转中常见取消短语（「取消」「停止」「别做了」等整句）自动转向——绕过队列直达正在执行的任务，在**下一个步骤边界**交给模型，让它据此收尾/调整（不保证立即停下；几步没动静请发 `/stop` 硬中断）；
- 安全边界：非本地会话（IM）只有**任务发起人**能转向（防群成员借当前回合的工具权限注入指令），他人拒绝文案引导 /stop；正在中断的回合拒绝新指令；指令 ≤4000 字；
- 可靠性：回合终态失败/中断时残留的未送达指令会被清理并明确告知「请重新发送」，不会泄漏到下一个任务；瞬断退避等待期也算流转中可转向；转向记录持久化（带发送者身份）；
- 审查闭环：electron-pro 两轮独立审查 + test-automator 边界修复（终态警告与失败兜底解耦，失败语义绝不被警告洗白）；复审 0H/2M/4L 可合并，M1/M2/L1-L4 记 follow-up。

## 变更二：延迟执行一律走定时任务，严禁回合内长阻塞（PR #70，现场驱动）

- 现场问题：对方说「1 小时后跟一次」，VE 在回合内轮询阻塞约 1.5 小时，会话队列卡死，后续消息全部进不来；
- 内置 prompt 新增规则（schedulerEnabled 时注入）+ `create_scheduled_task` description 双侧镜像：
  - **明确了时间**的一次性请求（「N 分钟/小时后」「到 X 点」）→ 必须建定时任务（cron 写具体时刻，下一个触发点即目标时间），当前回合只确认已建好并回复触发时间；
  - **时刻模糊**（「之后/回头跟一次」）→ 先报建议时间、对方确认后再建；
  - **严禁 sleep、循环轮询、回合内耗到时间点**；
  - cron 循环语义警示：任务到点执行后仍保留、明年同日会再触发——一次性任务的 prompt 末尾要写「完成后用 delete_scheduled_task 删除本任务」自我清理；提醒类不要开 silent；cron 最小粒度为分钟；
- 审查闭环（electron-pro）：H1「cron 具体时刻=只执行一次」错误表述修正（cron-parser 实证循环语义）；M1 与既有「仅创建明确要求的任务」口径收敛。follow-up：create_scheduled_task 原生 one-shot。

## 变更三：内置 pi-auto-research 自主研究技能（PR #67）

- `resources/skills/pi-auto-research`：查知识库 → 核对既有技能 → 联网查阅 → 本环境验证 → 沉淀知识库/固化技能的研究闭环；技能可见时自动内联注入；
- 能力降级教导（工具未注册跳过、权限被拒不绕过）；同名技能不自动合并；save_to_skill 开「验证后固化为可复用流程」通道（未经研究验证的流程不写技能）。

## 变更四：心跳汇报卡点占位改「暂无」（PR #68）

- 进行中任务没有已知障碍时卡点写「**暂无**」（无已知障碍是常态），不再是「暂未确认」（那是「没查清」）；三层语义：显式无 > 暂无 > 暂未确认；模型显式声明的「暂未确认」原样透传。
