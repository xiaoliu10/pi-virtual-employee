# 自主研究（auto-research）

## 何时使用
- 任务或问题在知识库（`search_knowledge_base`）和已有技能里都没有现成答案、步骤或口径。
- 需要查规则、政策、文档、文章、官方仓库（README / issue / 文档页）才能确定做法。
- 找到了候选方案，但还没在本环境实际验证过。

## 研究顺序（从近到远，逐级升级）
**以当前实际可用的工具为准**——下面的工具可能未注册或被禁用（管理员在设置里关闭了知识库/联网/学习等能力），按可用性降级，不要假设它们一定存在：
1. **知识库**：`search_knowledge_base`（未注册则跳过）用最具体的词先查；未命中换别名/同义表述再试一次。
2. **技能**：核对 available_skills 里是否有描述匹配的技能——有就严格按技能执行，不要绕过技能重新研究。
3. **联网**：`research_web` 查文章、规则、官方文档；开源/代码类问题优先查仓库的 README、文档页和 issue。**该工具未注册时**，用已启用的浏览器工具直接打开搜索结果/文档页面。若联网能力完全不可用，如实说明「当前没有联网研究能力」，不要声称查过了。
4. 都查不到才回复「暂未查到」，说明已经查过哪些渠道——禁止编造或凭印象作答。
5. **权限被拒 ≠ 工具不存在**：调用被拒时如实说明缺哪项能力，不得换其他工具绕过权限，也不得自行去开启开关。

## 验证（查到 ≠ 可以直接用）
- 能动手验证的就地验证：命令/代码用受控执行工具实际跑通；页面/流程用浏览器实际走一遍；规则类结论对照多个独立来源交叉印证。
- 危险操作仍走权限与「确认」门——验证不等于豁免确认。
- 无法在本环境验证（无权限/无环境）时，回复中明确标注「未经本地验证」并给出来源，不要断言为定论。

## 沉淀（验证通过后）
- **事实、答案、规则、口径** → `save_to_knowledge`（source="research"，带 sourceUrl）：标题概括主题，正文写清适用条件与步骤，便于下次检索直接命中。
- **可复用的操作流程**（验证通过、步骤可独立执行、同类任务还会再用）→ `save_to_skill` 固化为技能：description 写清何时触发，正文写标准步骤与完成标准；回复中说明已固化为技能及技能名，管理员可随时调整或删除。
- 未验证的内容不要沉淀为定论。
- **保存前先查重，避免重复堆积**：先检索知识库是否已有同主题条目——已有则按工具返回的更新语义（entryId + mode）修正它，不要另写一条；研究来源的条目不自动合并，重复保存会产生多条。
- **同名技能不会自动合并**：保存返回「已存在、需确认」时，说明冲突（已有哪些内容、想怎么改）并等管理员确认是否用 replace 覆盖，不得自行覆盖。
- **没有保存能力（工具未注册或被拒）时**：只交付研究结果与来源，明确说明「未能沉淀到知识库/技能」，不要声称已保存。
- 回复中的「已保存」必须以工具返回的成功结果为准。

## 回复口径
- 引用关键数字、时限、步骤时给出来源链接；区分「已在本环境验证」与「资料所说」。
- 沉淀后告知去向：已存入知识库（下次可直接命中）/ 已固化为技能（技能名）。
